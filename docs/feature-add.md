### Go Backend에 요구하는 기능
- FS 추상화 레이어 (Write, Read, Copy, Move, Delete, etc...)
- Chunk Upload 구현
	- 상세 구현 리스트는 다음과 같음
	- Chunk file 실시간 용량 감지 merge (디스크 가용 size의 20%만 사용 -> 나머지는 dist에 merge)
		- Chunk File을 저장하는 임시 공간의 스토리지와 실제로 파일이 저장되어야 하는 Dist 공간이 다를 수 있음. (ex. 200GB 파일을 업로드하려고 하는데 root fs는 128G, md0 위 LVM 볼륨은 4TB - 실제 저장 장소는 4TB 볼륨이지만 청크는 root fs에 쌓임.)
- 구성 파일 및 설정창 구현
	- 구성 파일은 기본적으로 사용하지 않는다. (현재는 sc.toml을 사용하지만, 아예 전면 제거)
	- 구성 파일을 사용하지 않게 되면, 만약 기존에는 잘 동작하던 설정이 환경 변화로 인해 동작하지 않을 수 있다. -- 이 경우 환경 변화로 인한 작동 불능 상태를 편집할 수 있는 emergency 모드를 제공한다.
	- 이로 인한 구성 파일 edit이 가능한 emergency webui를 기동할 수 있는 flag를 제공해야 하며, 이 webui는 마치 windows의 "안전 모드" 같은 역할을 한다. 접근은 관리자로 등록된 user의 credential을 이용한다.
	- 모든 설정은 데이터베이스에 저장한다. sc.toml이 아닌 데이터베이스만을 사용한다. sc.toml 편집과 같은 역할을 emergency 모드와 평상시 관리자 WebUI가 제공한다.
	- 모든 설정은 "저장" 버튼을 누른 즉시 dry run으로 검증을 거치며, 잘못된 설정일 경우 저장하지 않고 오류 메시지를 띄운다. (dry run 버튼이 있을 필요가 없음 -- 제거)
- SMB 컨테이너와의 통신, 설정 실시간 적용(특히 Web이나 API 관련)
	- SMB 컨테이너에는 이미 컨테이너 내부 sc-smb-control daemon이 있으므로, SMB 설정 변경이 감지될 경우(이 감지는 socket으로 통신하여 감지하건, fs 감지를 하건 더 빠르고 효율적인 방식으로 처리) SMB 서비스를 즉시 stop 후 start하여 변경사항을 적용한다. (docker container의 재시작이 필요 없어야 함)
	- 설정 실시간 적용도 동일하다. go에서 http 호스팅을 할 경우 설정이 변경될 때 웹서버의 설정이 바로 적용되는 것이 아니기에, 설정 변경이 있을 수 있는 레이어(ex. 공유 폴더 설정, bind address, 앱 호스트, 신뢰하는 프록시, etc..)의 경우 별도 프로세스 내지 스레드로 격리하여 그 레이어만 reboot 가능하도록 한다.
- 유저 편의성
	- 설정이 복잡하거나 알아듣기 힘들거나 너무 디테일하게 많으면 유저는 피곤해진다.
	- 모든 설정은 Web UI에서 적용하며, 서버가 잠시 중단되는(soft restart(프로세스 재시작 혹은 스레드 재시작)) 한이 있더라도 무조건적인 실시간 적용이 가능해야 하고, 동작해야 한다.
	- 위에서 설명한 "안전 모드(emergency mode)" 의 경우 항상 내부망(즉, smb 컨테이너가 감지한 enp0s6같은) 에서 접속 가능해야 한다. ip:port/emergency 로 접속하면 항상 응답해야 한다. 단, 보안 상 위험이 있으므로 관리자 권한 확인은 철저히 진행해야 한다. 보안 문제가 절대적으로 생겨서는 안되는 페이지이다. 이 이외에 core engine crash를 감지할 경우 자동으로 기본 링크(ex. ip:8443) 로 접속할 경우 /emergency로 바로 리다이렉트한다.
	- 기본적으로 첫 기동 시 내부망(smb 컨테이너가 감지한 enp0s6, eth0, etc.. 등의 실제 내부망)에서의 접속은 항상 가능해야 한다. 만약 여러 개의 실제 NIC가 있다면, 그 모든 곳에서 접속이 가능하게끔 우선 설정한다.
	- 첫 기동 시, 첫 설정 UI Form을 띄우고, 이 폼에는 Token이 있어야만 접근 가능하게끔 한다. 첫 기동 시 앱 호스트, 신뢰하는 프록시(비워도 됨, 선택), bind address(선택, 아무것도 없을 시 0.0.0.0:port로 공개), 공유 폴더 설정(선택, 아무것도 설정하지 않을 시 홈 페이지에서 Nothing Here! 라는 문구와 새 공유 폴더 버튼, 이 버튼을 눌러 첫 공유 폴더를 설정하세요라는 설명 문구도 띄운다.), 이 이외에 첫 설정이 제대로 안 되어있을 시 내부망에서의 첫 접속이 문제가 생길만 한 설정은 전부 여기서 설정 후 넘어간다.
	- Engine Crash, 원래 접근 가능했던 폴더가 사라진 경우(특히, 공유 폴더의 경로가 사라진 경우) 등의 문제가 발생할 시, 그냥 Crash 혹은 조용히 항목을 숨기는게 아닌, 사용자가 인지하고 수정 가능하게끔 한다.
