# Comprehensive Security and Architectural Audit: 2026-09-05

## 1. Executive Summary

This document presents a deep, code-level security and architectural audit of the Stowcloud repository. The analysis spans Go backend services, HTTP transports, WebDAV/Nextcloud compatibility endpoints, the upload pipeline, access control evaluation, and the SvelteKit frontend client.

The audit identifies seven security vulnerabilities (including one stored cross-site scripting flaw and two denial-of-service vectors), two concurrency and data-integrity defects, four frontend exception and reliability failures (including one release-blocking settings flaw), and multiple architectural layering anti-patterns. Every finding is grounded in source code with exact file paths and line ranges.

## 2. High-Severity Security Vulnerabilities

### 2.1 Stored Cross-Site Scripting (XSS) on Primary Application Origin
- **Rule ID**: SEC-XSS-01
- **Severity**: High
- **CWE**: CWE-79, CWE-434, CWE-116
- **Locations**:
  - `go/engine/lifecycle/filesread.go:211-263` (`sendStream`)
  - `go/engine/lifecycle/compatpreview.go:131-181` (`compatDirectStream`)
  - `go/engine/lifecycle/compatweb.go:85-86` (direct route registration)
  - `go/engine/lifecycle/compatweb.go:209-210` (`compatDirect`)
  - `go/engine/http/middleware/identity.go:62-84` (`CSP`)
- **Mechanism and Trace**:
  1. `sendStream` determines `Content-Type` using the file extension via `mime.TypeByExtension(filepath.Ext(entry.Name))`. When `attachAs` is empty, no `Content-Disposition` header is emitted.
  2. The Nextcloud compatibility route `GET /remote.php/direct/:claim` (registered in `compatweb.go:85-86`) routes to `compatDirectStream` on the primary application origin (`OriginApp`).
  3. `compatDirectStream` requires no browser session cookie or HTTP Basic authentication. It decrypts a 5-minute unbound `PurposeDownload` claim minted via `POST /ocs/v2.php/apps/dav/api/v1/direct` and invokes `sendStream` with `attachAs = ""` (inline stream).
  4. The primary application origin enforces a Content Security Policy (`identity.go:68-83`):
     ```
     default-src 'self'; script-src 'self' 'sha256-...'; ...
     ```
  5. An authenticated attacker uploads `evil.html` and `evil.js` into their own folder, minting two direct claims (`TOKEN_HTML` and `TOKEN_JS`). `evil.html` contains:
     ```html
     <script src="/remote.php/direct/TOKEN_JS"></script>
     ```
  6. The victim navigates to `https://app.example/remote.php/direct/TOKEN_HTML`. The response returns with `Content-Type: text/html; charset=utf-8` and no `Content-Disposition`.
  7. The browser loads `/remote.php/direct/TOKEN_JS`. Because it originates from the same host, the browser treats it as `'self'`, satisfying the CSP.
  8. The script executes within the victim's application origin, gaining access to the victim's session cookies, local storage, and the administrative API.
- **Remediation**:
  1. In `sendStream`, if `attachAs` is empty and the Content-Type is executable by a browser (such as `text/html`, `image/svg+xml`, `application/xhtml+xml`, `text/javascript`), force `Content-Disposition: attachment` under the entry's own name.
  2. Apply an overriding restricted CSP header on inline file responses:
     ```
     Content-Security-Policy: sandbox; default-src 'none'; base-uri 'none'; form-action 'none'
     ```
  3. Relocate `/remote.php/direct/:claim` strictly to the isolated content host (`OriginContent`).

### 2.2 Unauthenticated Argon2 Permit Exhaustion and Public Link Brute-Force
- **Rule ID**: SEC-DOS-01
- **Severity**: High
- **CWE**: CWE-770, CWE-307, CWE-400
- **Locations**:
  - `go/engine/lifecycle/publiclink.go:182-215` (`linkUnlock`)
  - `go/engine/lifecycle/publiclink.go:93-104` (`linkUnlocked`)
  - `go/engine/service/auth/password.go:38-43` (`GateConcurrency`)
  - `go/engine/service/auth/password.go:29-38` (`CurrentParams`)
  - `go/engine/lifecycle/open.go:425-435`
- **Mechanism and Trace**:
  1. `linkUnlock` (handling `POST /s/:token/auth`) performs password verification through `e.Core.LinkCheckPassword`. This routes directly to `e.Auth.Verify`, which calls `s.gate.acquire(ctx)`.
  2. `GateConcurrency` is set to 4. Argon2id runs with 48 MiB memory and 3 iterations, taking 60 to 120 ms per invocation.
  3. `POST /s/:token/auth` contains no sliding-window login rate limiter (such as the 10 attempts per 5 minutes rule in `login.go:41-43`). The only check is the global token bucket (default 20 req/s, burst 100).
  4. Crucially, `linkUnlocked` runs on every request to a password-protected link (`GET /s/:token`, `GET /s/:token/download`, `GET /s/:token/zip`, `POST /s/:token/drop`). Because the cookie stores the plaintext password, `linkUnlocked` re-runs Argon2id on each request.
  5. An unauthenticated attacker sending 10 to 20 requests per second to `/s/:token/auth` or `/s/:token/download` completely exhausts all four Argon2 concurrency permits.
  6. Every legitimate user attempting to log in or authenticate via HTTP Basic or WebDAV is blocked in `gate.acquire`, causing complete server-wide authentication denial-of-service.
  7. Furthermore, the absence of a per-token attempt budget allows link passwords to be brute-forced at 20 guesses per second with no lockout or audit recording.
- **Remediation**:
  1. Introduce an `AttemptBudget` sliding window on `linkUnlock`, keyed on both the client IP and the link ID (e.g. 10 attempts per 5 minutes).
  2. Log failed unlock attempts via `AppendAudit` with a `link.unlock` event.
  3. Do not re-verify Argon2 on subsequent requests in `linkUnlocked`; replace with an HMAC unlock ticket (see SEC-CRED-01).

### 2.3 Plaintext Password Stored in Base64 Public Link Cookie
- **Rule ID**: SEC-CRED-01
- **Severity**: Medium
- **CWE**: CWE-522, CWE-312
- **Locations**:
  - `go/engine/lifecycle/publiclink.go:203-213` (`linkUnlock`)
  - `go/engine/lifecycle/publiclink.go:93-104` (`linkUnlocked`)
- **Mechanism**:
  When a visitor unlocks a password-protected link, `linkUnlock` writes:
  ```go
  c.Cookie(&fiber.Cookie{
      Name:  linkCookie(link.ID),
      Value: base64.RawURLEncoding.EncodeToString([]byte(req.Password)),
      Path:     PublicLinkPrefix + "/" + c.Params("token"),
      HTTPOnly: true,
      Secure:   true,
      SameSite: "Lax",
  })
  ```
  The plaintext link password is stored as reversible Base64 in the client cookie. Anyone with access to browser storage, memory dumps, or diagnostics recovers the password in plaintext.
- **Remediation**:
  Store an HMAC ticket bound to the stored password hash and timestamp:
  ```go
  func linkTicket(key []byte, linkID int64, storedHash string, expiresNs int64) string
  ```
  When the password is changed, the stored hash changes, which automatically invalidates all outstanding tickets without storing secrets in cookies.

### 2.4 OIDC Link Fails to Disable Local Password Authentication
- **Rule ID**: SEC-OIDC-01
- **Severity**: High
- **CWE**: CWE-287, CWE-863
- **Locations**:
  - `go/engine/service/auth/oidcbridge.go:98-109` (comment)
  - `go/engine/service/auth/oidcbridge.go:141-143` (`LinkOIDC`)
  - `go/engine/store/state/oidclink.go:173-204` (`CreateOIDCLink`)
  - `go/engine/service/auth/login.go:38-120` (`Login`)
  - `go/engine/service/auth/login.go:173-219` (`VerifyPassword`)
- **Mechanism**:
  1. `oidcbridge.go:98-103` explicitly asserts:
     "The password credential goes because it is the factor being replaced: leaving it means the account still answers to the password the provider was just put in front of."
  2. However, `LinkOIDC` only disables SMB access:
     ```go
     func (s *Service) LinkOIDC(ctx context.Context, userID int64) error {
         return s.setSMBEnabled(ctx, userID, false)
     }
     ```
  3. `state.CreateOIDCLink` never clears or alters `user.pw_hash`.
  4. In `login.go`, `Login()` and `VerifyPassword()` verify `acct.PwHash` without checking for the presence of an OIDC link.
  5. As a result, an account linked to an enterprise single sign-on provider continues to authenticate using its legacy local password, bypassing provider MFA, device posture checks, and conditional access policies.
- **Remediation**:
  1. In `state.CreateOIDCLink`, clear the password hash (`UPDATE user SET pw_hash = '' WHERE id = ?`).
  2. In `Login()` and `VerifyPassword()`, check `s.store.OIDCLinkOf(ctx, acct.ID)` and reject local password login with a burned decoy hash to prevent timing oracles.

### 2.5 Trusted Proxy Wildcard 0.0.0.0/0 Permitted as Advisory
- **Rule ID**: SEC-NET-01
- **Severity**: Medium
- **CWE**: CWE-345, CWE-290
- **Locations**:
  - `go/engine/service/settings/check/check.go:317-320` (`checkProxies`)
  - `go/engine/http/middleware/client.go:38-56` (`ClientAddr`)
  - `go/engine/http/emergency/emergency.go:148-160` (`gate`)
- **Mechanism**:
  1. `checkProxies` flags `0.0.0.0/0` (`p.Bits() == 0`) as an `advisory` instead of a `rejection`.
  2. If an administrator saves `0.0.0.0/0`, all network peers are treated as trusted proxies.
  3. In `client.go:50-53`, `parseAddr(cfConnecting)` takes precedence. If an external client sends `CF-Connecting-IP: 127.0.0.1`, `ClientAddr` immediately returns `127.0.0.1`.
  4. This satisfies `netzone.IsPrivate` in `emergency.go:150` and `lifecycle/mount.go:324-347` (`health`), allowing external attackers to access the emergency safe mode interface and private health checks.
- **Remediation**:
  Promote `p.Bits() == 0` to a hard validation rejection in `checkProxies`.

### 2.6 Active Sessions Retained on Password Reset
- **Rule ID**: SEC-SESS-01
- **Severity**: Low
- **CWE**: CWE-613
- **Locations**:
  - `go/engine/service/auth/users.go:80-104` (`SetPassword`)
- **Mechanism**:
  `SetPassword` explicitly avoids terminating sessions:
  ```go
  // Sessions survive: a session is not a credential, and signing somebody out
  // of every device because they changed their own password is a surprise
  // rather than a security property.
  ```
  If an account is compromised via stolen session cookies, changing the password does not invalidate the attacker's active sessions.
- **Remediation**:
  Call `s.store.DeleteSessionsOf(ctx, userID)` inside `SetPassword`.

## 3. Concurrency and Access Control Deficiencies

### 3.1 Upload Engine Concurrent PATCH Chunk Corruption
- **Rule ID**: CONC-UPLOAD-01
- **Severity**: High
- **CWE**: CWE-362, CWE-662
- **Locations**:
  - `go/engine/service/upload/spool.go:35-100` (`PatchAt`)
  - `go/engine/service/upload/spool.go:150-205` (`writeBodyAt`)
  - `go/engine/service/upload/engine.go:60-69`, `217-238` (`handleFor`)
- **Mechanism**:
  1. `PatchAt` acquires the row lock (`e.lockRow(id)`), checks ownership, validates the chunk offset, and obtains the descriptor handle `f` from `handleFor`.
  2. `PatchAt` calls `unlock()` at line 75, releasing the row lock before streaming the request body.
  3. `engine.go:60-63` notes that chunk writes acquire the handle lock followed by the row lock. However, `PatchAt` never locks `h.mu`, and `handleFor` only locks `handlesMu` while creating the handle map entry.
  4. If two concurrent PATCH requests target overlapping offsets, both pass offset validation and invoke `writeBodyAt` simultaneously on descriptor `f`.
  5. `writeBodyAt` issues multiple 256 KiB `pwrite` calls. These calls interleave on disk without synchronization, corrupting file contents.
  6. The chunk checksum is calculated over incoming network bytes, not on-disk bytes, so both corrupted requests report successful checksum verification.
- **Remediation**:
  Retain `h.mu.Lock()` on the descriptor handle throughout the execution of `writeBodyAt`.

### 3.2 ACL Zero-Permission Deny Bypass and Blind PROPFIND Inheritance
- **Rule ID**: ACL-EVAL-01
- **Severity**: Medium
- **CWE**: CWE-863, CWE-280
- **Locations**:
  - `go/engine/service/acl/eval.go:157-195` (`evaluateLocked`)
  - `go/engine/service/acl/eval.go:244-251` (`findDeny`)
  - `go/engine/service/core/resolve.go:203-217` (`ResolveUnder`)
  - `go/engine/http/dav/propfind_method.go:336-342` (`resolveChild`)
- **Mechanism**:
  1. In `evaluateLocked`, `findDeny` checks `level[i].Deny.Intersects(want)`.
  2. When `want == 0` (as in `Resolve(user, path, 0)`), `Deny.Intersects(0)` evaluates to false. A deny-only rule (`Allow: 0, Deny: 0xFFFF`) at depth 2 is skipped.
  3. `findAnyAllow` sees an empty allow set and continues to depth 0, where the share root allow rule returns `Allowed: true`.
  4. In WebDAV PROPFIND, `resolveChild` calls `h.core.ResolveUnder(parent, p, 0)`.
  5. `ResolveUnder` never consults the evaluator. It copies `parent.perms` directly onto the child.
  6. During `Depth: infinity` PROPFIND walks, a child folder with an explicit deny grant inherits its parent's allow permissions, leaking metadata (names, sizes, timestamps, etags) of the denied subtree.
- **Remediation**:
  1. In `evaluateLocked`, when `want.IsEmpty()`, return `Allowed: false` if any grant at that level has a non-empty `Deny` set.
  2. Update `ResolveUnder` to re-evaluate the child's effective permissions:
     ```go
     perms := c.acl.Effective(int64(parent.user), at) & parent.perms
     ```
  3. In `resolveChild`, pass `acl.Read` instead of 0.

## 4. Frontend Reliability and Exception Handling Gaps

### 4.1 SMB Access Switch Setting Inoperable on Real Backend
- **Rule ID**: FE-SMB-01
- **Severity**: High (Release Blocker)
- **Locations**:
  - `web/src/lib/api/http.ts:1094-1096` (`updateSmbSettings`)
  - `web/src/lib/ui/settings/SmbSection.svelte:78-88` (`apply`)
  - `go/engine/lifecycle/smb.go:33-52`
- **Mechanism**:
  1. `updateSmbSettings` sends:
     ```ts
     body: JSON.stringify({ opt_out: optOut, enabled })
     ```
  2. The server route `POST /api/v1/account/smb` requires password reconfirmation:
     ```go
     e.reconfirm(c, owner, req.Current)
     ```
     When `req.Current` is empty, it returns 401 `auth.invalid_credentials`.
  3. The mock implementation (`mock.ts:1230-1234`) does not enforce password reconfirmation, masking this bug during development.
  4. In `SmbSection.svelte:180,183`, `checked={enabled}` is passed one-way. On failure, `apply()` catches the error and displays a generic message without resetting the switch, leaving the UI switch visually flipped while the backend rejected the mutation.
- **Remediation**:
  Add password reconfirmation to `updateSmbSettings` and reset the UI switch state on failure.

### 4.2 Missing Fetch Timeout and Silent Empty Object Parsing
- **Rule ID**: FE-NET-01
- **Severity**: Medium
- **Locations**:
  - `web/src/lib/api/http.ts:88-103` (`request<T>`)
  - `web/src/lib/api/http.ts:122-130` (`send`)
- **Mechanism**:
  1. `fetch` does not supply a default timeout signal. Stalled reverse proxies leave requests hanging indefinitely, causing loading spinners to freeze permanently.
  2. `request<T>` executes `const body = await res.json().catch(() => ({}))`. If a reverse proxy returns 200 OK with an HTML error page or empty response, `body` resolves to `{}`. Callers expecting typed objects (such as `{ entries: [] }`) crash with `TypeError: Cannot read properties of undefined`.
- **Remediation**:
  Set a 30-second default timeout using `AbortSignal.timeout(30_000)` and throw an `ApiError` when 2xx responses fail to parse as JSON.

### 4.3 Misleading Administrator Creation Error in Setup Flow
- **Rule ID**: FE-SETUP-01
- **Severity**: Low
- **Locations**:
  - `web/src/routes/setup/+page.svelte:88-99` (`enter`)
  - `web/src/routes/setup/+page.svelte:119-153` (`submit`)
- **Mechanism**:
  `submit` calls `await createInitialAdmin(...)` followed by `await enter()`. If `enter()` throws (e.g. rate limited or temporary socket drop on login), the shared catch block routes the error through `messageFor`, displaying "Could not create administrator account".
  The account was already created in the database. When the user retries, the server returns "Setup already completed", confusing the operator.
- **Remediation**:
  Wrap `enter()` in an isolated try/catch block that sets `doneButLoginFailed = true` upon login failure and redirects to `/login`.

### 4.4 Exception Context Swallowed in Settings Modals
- **Rule ID**: FE-UI-01
- **Severity**: Low
- **Locations**:
  - `web/src/lib/ui/settings/AppPasswordsSection.svelte:99-143` (`confirmRevoke`, `confirmWipe`)
  - `web/src/lib/ui/settings/PasswordSection.svelte:57-68`
- **Mechanism**:
  1. In `AppPasswordsSection.svelte`, `confirmRevoke` and `confirmWipe` catch all errors and only act if `err.status === 404`. For any other error (such as 401 session expiry or 429 rate limit), the catch block exits silently, leaving the modal stuck open with no error message.
  2. In `PasswordSection.svelte`, `auth.rate_limited` falls into the generic `else` branch, displaying an error under the current password input. This misleads the user into thinking the password was mistyped, encouraging repeated attempts that prolong the rate limit lockout.
- **Remediation**:
  Explicitly handle `auth.rate_limited` and surface descriptive error messages in modal catch blocks.

## 5. Architectural and Code Quality Analysis

### 5.1 Monolithic Lifecycle Package
- **Location**: `go/engine/lifecycle/` (52 files, 13,288 non-test lines, 266 methods on `Engine`)
- **Problem**:
  The `lifecycle` package acts as an architectural god package. In addition to application orchestration, it directly accesses `e.State` (`*state.DB`) instead of delegating through service layers:
  - `compatdav_on.go:110` executes direct queries to `e.State.Favorites`.
  - `configsecret.go:28-66` performs direct database read/write/delete operations for configuration secrets.
  - `tasks.go:47,114,117` directly executes database lock sweeps and login flow cleanups.
  This bypasses service encapsulation and prevents modular testing.
- **Recommendation**:
  Extract dedicated service modules:
  1. `service/favorite`: Encapsulate favorites management.
  2. `service/settings/secret`: Encapsulate configuration secret sealing and storage.
  3. Route sweeps in `tasks.go` uniformly through service interfaces.

### 5.2 PROPFIND N+1 Query Anti-Pattern
- **Location**: `go/engine/lifecycle/compatdav_on.go:105-120`
- **Problem**:
  In `davVendorProps`, the closure for property emission checks `favorite` by executing `e.State.Favorites(ctx, user)` on every entry. On a directory of 5,000 files, a single Depth: 1 PROPFIND triggers 5,000 SQLite database queries.
- **Recommendation**:
  Cache favorites once per request within the request context: `favoritesOf(ctx, e, user)`.

### 5.3 Concurrent Index Build Corruption
- **Location**: `go/engine/lifecycle/searchindexbuild.go:150-164` (`adminIndexBuild`)
- **Problem**:
  `adminIndexBuild` checks `e.Search.HasIndex()` and starts a goroutine without checking if a build is already in progress. `state.CreateOp` allows duplicate operation rows.
  If build A reaches the corpus limit and sets `ix.SetIncomplete(true)`, a concurrent build B starting later will clear the incomplete flag upon finishing. This leaves a partial index marked complete, causing searches to silently return incomplete results.
- **Recommendation**:
  Use an atomic boolean flag (`indexBuilding atomic.Bool`) to serialize index builds and reject overlapping requests with 429 or 503.

### 5.4 Dual State Management Layer in Web Client
- **Location**: `web/src/lib/state/*` vs `web/src/lib/store/slices/*`
- **Problem**:
  State logic is duplicated between functional Zustand slices and Svelte 5 rune wrappers. Multiple Zustand exports (`createBrowseStore`, `pureApplyPage`, `createSelectionStore`) have zero production consumers and are only referenced by unit tests.
- **Recommendation**:
  Standardize on Svelte 5 runes for UI reactivity, retain pure utility functions in slices, and prune unused Zustand store wrappers and associated dead tests.

## 6. Verified Solid Implementations

1. **Kernel-Enforced Atomic VFS Paths**: `go/engine/infra/vfs/open.go` requires Linux `openat2` with `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV`. Path traversal and symlink escape vulnerabilities are prevented atomically at the syscall boundary.
2. **Preview Worker Sandboxing**: `go/engine/service/preview/worker/worker.go` executes image decoding inside an isolated child process restricted by Landlock, Seccomp (blocking open syscalls), RLIMIT memory bounds, and closed inherited descriptors.
3. **Argon2id Concurrency Protection**: `go/engine/service/auth/password.go` regulates memory-hard hashing through a buffered 4-permit channel, protecting server memory against exhaustion.
4. **Strict Architectural Layer Gate**: `go/tools/layercheck` enforces unidirectional module imports (`kit` -> `infra`/`store` -> `service` -> `http` -> `lifecycle`), preventing cyclical dependencies.
5. **Internationalization Parity**: `web/src/lib/i18n/ko.json` and `en.json` contain 928 identical keys with complete parity.
