# Security and Quality Audit: 2026-09-05

## 1. Executive Summary

This audit assesses the Stowcloud repository across backend Go services, HTTP transport, file operations, compatibility layers, and SvelteKit frontend components.

The evaluation identified eight security vulnerabilities, two concurrency and logic defects, three frontend exception handling deficiencies, and several architectural boundaries requiring refactoring. Key highlights include an origin-level Stored XSS vulnerability in inline file reads, an unauthenticated denial-of-service vector against Argon2 password verification on public links, and an OIDC password deactivation failure.

---

## 2. Security Vulnerabilities

### 2.1 Stored Cross-Site Scripting (XSS) on Primary Application Origin
- **Severity**: High
- **Location**: `go/engine/lifecycle/filesread.go:31-55` (`filesRead`), `go/engine/lifecycle/filesread.go:201-240` (`sendStream`), `go/engine/http/middleware/identity.go:62-84` (`CSP`)
- **Evidence**:
  ```go
  // filesread.go:31-37
  func (e *Engine) filesRead(c *fiber.Ctx) error {
      owner, ok := ownerOf(c)
      if !ok {
          return refuse(c, apierr.Classified{Class: apierr.AuthRequired})
      }
      r, err := e.resolve(owner, c.Query("path"), acl.Download)
      if err != nil {
          return fail(c, err)
      }
      return e.streamFile(c, r, "")
  }
  ```
  In `sendStream`, when `attachAs` is empty:
  ```go
  // filesread.go:214-234
  contentType := mime.TypeByExtension(filepath.Ext(entry.Name))
  if contentType == "" {
      contentType = fiber.MIMEOctetStream
  }
  c.Set(fiber.HeaderContentType, contentType)
  // attachAs is empty, so Content-Disposition is omitted:
  if attachAs != "" {
      c.Set(fiber.HeaderContentDisposition, handler.ContentDisposition(attachAs))
  }
  ```
  In `identity.go`:
  ```go
  // identity.go:68-71
  directives := []string{
      "default-src 'self'",
      "script-src " + strings.Join(script, " "), // script contains "'self'"
  ```
- **Mechanism and Impact**:
  `/api/v1/files/read` executes under the primary application host (`OriginApp`). If a user uploads an HTML file containing `<script src="/api/v1/files/read?path=shared/exploit.js"></script>` or an SVG containing embedded scripts, the file is returned with `Content-Type: text/html` or `image/svg+xml` and no `Content-Disposition: attachment`.
  Because the Content Security Policy permits scripts from `'self'`, the browser executes the script in the context of the authenticated user's session, granting access to session cookies, local storage, and the administration API.
- **Suggested Fix**:
  Responses from `/api/v1/files/read` must apply `Content-Security-Policy: sandbox; default-src 'none'`. Alternatively, browser-executable formats (such as HTML, HTM, SVG) must force `Content-Disposition: attachment` unless served from an isolated untrusted content domain (`OriginContent`).

### 2.2 Unauthenticated Public Link Brute-Force and Argon2 Resource Exhaustion
- **Severity**: High
- **Location**: `go/engine/lifecycle/publiclink.go:182-213` (`linkUnlock`), `go/engine/service/auth/password.go:40-44` (`GateConcurrency`)
- **Evidence**:
  ```go
  // publiclink.go:182-201
  func (e *Engine) linkUnlock(c *fiber.Ctx) error {
      link, _, err := e.Core.LinkPublic(c.UserContext(), c.Params("token"))
      if err != nil {
          return fail(c, err)
      }
      var req struct {
          Password string `json:"password"`
      }
      if derr := decodeBody(c, &req); derr != nil {
          return refuse(c, apierr.Classified{Class: apierr.Malformed})
      }
      ok, cerr := e.Core.LinkCheckPassword(c.UserContext(), link, req.Password)
      if cerr != nil {
          return fail(c, cerr)
      }
      if !ok {
          return refuse(c, linkPasswordRefusal())
      }
  ```
  `LinkCheckPassword` performs Argon2id verification through `s.gate.acquire`:
  ```go
  // password.go:40-43
  const GateConcurrency = 4
  ```
- **Mechanism and Impact**:
  `POST /s/:token/auth` contains no IP or token-based sliding window rate limiter.
  1. Attackers can brute-force short link passwords without throttle.
  2. Because Argon2id consumes 48 MiB and runs through a global concurrency gate capped at 4 permits, an unauthenticated attacker sending 10 concurrent requests to `/s/:token/auth` saturates all Argon2 execution slots, blocking standard user sign-ins across the server.
- **Suggested Fix**:
  Add an IP and token rate limiter to `linkUnlock` mirroring the login limiter in `auth.go`.

### 2.3 Plaintext Password Ingestion in Base64 Public Link Cookie
- **Severity**: Medium
- **Location**: `go/engine/lifecycle/publiclink.go:203-211` (`linkUnlock`), `93-104` (`linkUnlocked`)
- **Evidence**:
  ```go
  // publiclink.go:203-211
  c.Cookie(&fiber.Cookie{
      Name:  linkCookie(link.ID),
      Value: base64.RawURLEncoding.EncodeToString([]byte(req.Password)),
      Path:     PublicLinkPrefix + "/" + c.Params("token"),
      HTTPOnly: true,
      Secure:   true,
      SameSite: "Lax",
  })
  ```
- **Mechanism and Impact**:
  When a link is unlocked, the plain password string is base64-encoded and stored as the cookie value. While scoped to the link path, anyone inspecting client storage or shared browser profiles can decode the plaintext password directly.
- **Suggested Fix**:
  Generate an ephemeral unlock token or HMAC signature over the link ID and session secret rather than persisting the raw password in the client cookie.

### 2.4 OIDC Link Fails to Invalidate Local Password Authentication
- **Severity**: Medium
- **Location**: `go/engine/service/auth/oidcbridge.go:98-109`, `141-143` (`LinkOIDC`), `go/engine/service/auth/login.go:38-120` (`Login`)
- **Evidence**:
  The design comment in `oidcbridge.go:98-103` asserts:
  "The password credential goes because it is the factor being replaced: leaving it means the account still answers to the password the provider was just put in front of."
  However, `LinkOIDC` only disables SMB file sharing:
  ```go
  // oidcbridge.go:141-143
  func (s *Service) LinkOIDC(ctx context.Context, userID int64) error {
      return s.setSMBEnabled(ctx, userID, false)
  }
  ```
  `login.go:38-120` executes password verification without checking whether an OIDC identity link is bound:
  ```go
  // login.go:45-67
  acct, err := s.store.AccountByName(ctx, req.Name)
  // ... verifies password hash directly
  ok, stale, err := s.Verify(ctx, acct.PwHash, req.Password)
  ```
- **Mechanism and Impact**:
  Users who bind an external SSO identity to enforce corporate identity provider access retain active local passwords. An adversary holding the old password can sign in directly via `/api/v1/auth/login`, bypassing single sign-on constraints.
- **Suggested Fix**:
  Store an explicit `password_disabled` status on the account row or verify in `Login()` that no active OIDC link exists for the account.

### 2.5 Trusted Proxy Wildcard 0.0.0.0/0 Permitted as Advisory
- **Severity**: Medium
- **Location**: `go/engine/service/settings/check/check.go:317-320` (`checkProxies`)
- **Evidence**:
  ```go
  // check.go:317-320
  if p, perr := netip.ParsePrefix(entry); perr == nil && p.Bits() == 0 {
      out = append(out, advisory(in.Section, "trusted_proxies", keyProxyIsEverything, "value", c))
  }
  ```
- **Mechanism and Impact**:
  A prefix of `0.0.0.0/0` is recorded as an `advisory` instead of a `rejection`. If an administrator saves this configuration, `trustedPeer` in `client.go` evaluates all peers as trusted proxies. An external client can supply arbitrary `X-Forwarded-For: 127.0.0.1` headers to bypass the private network gate on `/emergency` and `/api/v1/system/health`.
- **Suggested Fix**:
  Promote `p.Bits() == 0` to a hard validation rejection in `checkProxies`.

### 2.6 Password Change Retains Stolen Active Sessions
- **Severity**: Low
- **Location**: `go/engine/service/auth/users.go:80-104` (`SetPassword`)
- **Evidence**:
  ```go
  // users.go:80-84
  // Sessions survive: a session is not a credential, and signing somebody out
  // of every device because they changed their own password is a surprise
  // rather than a security property.
  func (s *Service) SetPassword(ctx context.Context, userID int64, newPW secret.Secret) error {
  ```
- **Mechanism and Impact**:
  If an account is compromised via a stolen session cookie, changing the account password does not revoke existing active session records. The attacker's stolen session remains valid until its absolute lifetime expires.
- **Suggested Fix**:
  Invoke `s.store.DeleteSessionsOf(ctx, userID)` within `SetPassword` to terminate all existing sessions upon password reset.

## 3. Bug-Prone Concurrency and Logic Defects

### 3.1 Upload Engine Concurrent PATCH Data Corruption
- **Severity**: High
- **Location**: `go/engine/service/upload/spool.go:35-100` (`PatchAt`), `go/engine/service/upload/engine.go:60-69`, `217-236` (`handleFor`)
- **Evidence**:
  ```go
  // spool.go:39-75
  unlock := e.lockRow(id)
  r, err := e.load(ctx, id)
  // ... validates offset
  unlock() // Lock released before writing data
  
  // spool.go:84-88
  n, digest, werr = e.writeBody(f, off, body, r, sum)
  ```
  `engine.go:60-63` states that chunk writes acquire the handle lock followed by the row lock. However, `PatchAt` never acquires `h.mu`, and `handleFor` only locks `handlesMu` to allocate the descriptor.
- **Mechanism and Impact**:
  If two concurrent PATCH requests targeting identical or adjacent offsets arrive (due to client retry or multiple network paths), both pass `validateOffset` and execute `writeAllAt` concurrently on descriptor `f`.
  In Linux, simultaneous `pwrite` calls on the same file descriptor without synchronization interleave 256 KiB blocks, corrupting the assembled file.
- **Suggested Fix**:
  Hold `h.mu.Lock()` on the descriptor handle throughout the execution of `writeBody` to serialize file writes.

### 3.2 ACL evaluateLocked Zero-Permission Deny Bypass
- **Severity**: Medium
- **Location**: `go/engine/service/acl/eval.go:157-195` (`evaluateLocked`), `244-251` (`findDeny`)
- **Evidence**:
  ```go
  // eval.go:167-181
  if g := findDeny(level, want); g != nil {
      return Decision{Allowed: false, By: g.ID}
  }
  if want.IsEmpty() {
      if g := findAnyAllow(level); g != nil {
          return Decision{Allowed: true, By: g.ID}
      }
      continue
  }
  ```
  `findDeny` checks whether `level[i].Deny.Intersects(want)`:
  ```go
  // eval.go:244-251
  func findDeny(level []Grant, want Perms) *Grant {
      for i := range level {
          if level[i].Deny.Intersects(want) {
              return &level[i]
          }
      }
      return nil
  }
  ```
- **Mechanism and Impact**:
  When evaluating reachability with zero permissions (`want == 0`, as in `Resolve(user, path, 0)`), `Deny.Intersects(0)` evaluates to false. If a subdirectory has an explicit Deny-all grant, `findDeny` returns nil.
  The evaluator then traverses up the directory tree (`depth--`). If the parent share root has an Allow grant, `findAnyAllow` returns true. The caller is incorrectly informed that the denied subdirectory is reachable.
- **Suggested Fix**:
  When `want.IsEmpty()`, check if `level` contains any deny rule covering all access (`level[i].Deny != 0`), and return `Allowed: false` immediately.

## 4. Frontend Error Handling and Exception Gaps

### 4.1 Missing Fetch Timeout and Silent Invalid JSON Coercion
- **Severity**: Medium
- **Location**: `web/src/lib/api/http.ts:88-103` (`request<T>`)
- **Evidence**:
  ```ts
  const res = await fetch(`${BASE}${path}`, { ...init, method, headers, credentials: 'include' })
  if (res.status === 204) return undefined as T
  const body = await res.json().catch(() => ({}))
  if (!res.ok) throw errorFrom(res, body)
  return body as T
  ```
- **Mechanism and Impact**:
  1. Requests lack default `AbortSignal.timeout`. Network deadlocks or stalled proxies cause promises to hang indefinitely.
  2. If a reverse proxy returns 200 OK with an empty body or HTML gateway text, `res.json().catch()` swallows the parse error and returns `{}`. Downstream components expecting typed structures (e.g. `res.entries.map(...)`) crash with `TypeError: Cannot read properties of undefined`.
- **Suggested Fix**:
  Add an explicit timeout (e.g. 30 seconds) via `AbortSignal.timeout` and reject with an `ApiError` if a 2xx response contains unparseable non-JSON payloads.

### 4.2 Misleading Administrator Setup Failure Message
- **Severity**: Low
- **Location**: `web/src/routes/setup/+page.svelte:88-150`
- **Evidence**:
  ```ts
  // setup/+page.svelte:147-150
  await enter()
  } catch (err) {
    errorMsg = messageFor(err)
  }
  ```
  `enter()` invokes `api.login(username, password)`. If login fails after successful account creation (for example due to network instability), `messageFor` defaults to `t('setup.could_not_create_administrator_account')`.
- **Mechanism and Impact**:
  The user is informed that administrator creation failed, even though the database transaction committed. Subsequent setup attempts report "Setup already completed", confusing the operator.
- **Suggested Fix**:
  Wrap `enter()` in a distinct try/catch block that acknowledges successful creation and directs the operator to `/login`.

### 4.3 Error Context Swallowing in Settings Modals
- **Severity**: Low
- **Location**: `web/src/lib/ui/settings/AppPasswordsSection.svelte:73-75`
- **Evidence**:
  ```svelte
  try {
    const res = await api.createAppPassword(newName.trim(), newCurrent)
  } catch {
    createModal.fail(t('app_password.could_not_create_app_password'))
  }
  ```
- **Mechanism and Impact**:
  The catch handler discards the caught error. If the current password was invalid (`auth.invalid_credentials`), the UI renders a generic failure message rather than notifying the user of the invalid password.
- **Suggested Fix**:
  Inspect `err instanceof ApiError` and display field-specific validation errors.

## 5. Architectural and Structural Observations

### 5.1 Monolithic Lifecycle Package (`go/engine/lifecycle`)
- **Status**: Structural Debt
- **Details**:
  `go/engine/lifecycle` contains 46 Go files and approximately 17,000 lines of code. It coordinates startup, WebDAV protocols, OCS Nextcloud endpoints, upload spooling, archive streaming, background tasks, and event routing.
  Crucially, several components in `lifecycle` directly manipulate `e.State` (`*state.DB`), bypassing service abstraction boundaries:
  - `compatdav_on.go`: Direct database queries for instance IDs and favorites.
  - `configsecret.go`: Direct reads and writes of sealed configuration secrets.
  - `tasks.go`: Direct invocation of database lock sweep functions.
- **Recommendation**:
  Separate HTTP handler clusters into dedicated modules (`http/dav`, `http/compat`, `http/files`) and route all state mutations through service interfaces.

### 5.2 Dual State Layer in Web Frontend
- **Status**: Maintenance Risk
- **Details**:
  State management is split between functional Zustand slices in `web/src/lib/store/slices/*` and Svelte 5 rune wrappers in `web/src/lib/state/*`.
  While backward-compatible adapters exist, having duplicate definitions for `selection`, `browse`, and `upload-tray` increases cognitive load and risks state desynchronization.
- **Recommendation**:
  Standardize on Svelte 5 runes for UI-bound stores and retire the legacy adapter layer.

### 5.3 Oversized Svelte Components
- `web/src/routes/(app)/b/[...path]/+page.svelte`: 1,781 lines
- `web/src/lib/ui/admin/ServerSettingsSection.svelte`: 1,307 lines
- `web/src/lib/ui/admin/LogsSection.svelte`: 1,131 lines
- `web/src/lib/ui/FileGrid.svelte`: 906 lines
These components manage toolbar actions, keyboard bindings, modals, and batch tasks in single script blocks. They should be decomposed along logical sub-surface boundaries.

## 6. Verified Solid Implementations

- **Kernel Atomic VFS Confinement**: `go/engine/infra/vfs/open.go` uses Linux `openat2` with `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS`, eliminating race conditions and symlink escapes at the kernel layer.
- **Preview Worker Sandboxing**: `go/engine/service/preview/worker/worker.go` executes decoding in an isolated child process confined by Landlock, Seccomp (blocking open syscalls), and strict resource limits.
- **Argon2id Concurrency Gate**: `go/engine/service/auth/password.go` restricts concurrent Argon2id hashing via a 4-permit channel, protecting memory allocation.
- **CSRF Double-Check Mechanism**: State-changing requests under session cookie authority require the `Sc-Csrf` token derived from the session secret, reinforced by the Host and Origin boundary gate.
- **Internationalization Parity**: Verification showed 928 keys in `ko.json` and `en.json` with zero missing mappings across both locales.
