## The rule that governs everything here

From `docs/refactor/README.md`: `go/internal/` is a **behavioural
specification only**. Nothing is copied into `go/engine/`, comments included.
`scripts/verify.sh` runs `tools/freshscan`, which diffs the two trees' comment
lines and fails on a match. It caught four lines across this session's work,
one of them in a test comment I had written while reading the old hub. Read the
old code, close it, and write what is true of the new code.

## What is left before a cutover

Two things, and the route count is no longer one of them.

1. **dav and compat have their vocabulary and none of their handlers.**
   `engine/http/dav` is 1,759 lines of If-header grammar, XML scanning,
   PROPFIND and PROPPATCH parsing, multistatus writing, href encoding and the
   method-to-permission table, with no handler for a single method.

   Measured rather than estimated, because an earlier draft of this line was
   low by half. `internal/dav` is 4,176 lines in the package plus 864 more in
   `internal/server/davmount.go` and `internal/store/state/dav.go`, 5,040
   together. About 1,641 of the package is the parsing and vocabulary the
   engine has already rebuilt. The handler side proper, content negotiation
   and ranges, locking, the write methods and upload handling, is 1,650, and
   the rest is wiring and state. `compat` is 1,178 in the engine against 4,457
   in `internal`.
2. **The public link surface is absent.** Five routes under `/s/{token}`:
   landing, password gate, download, zip, drop upload. Link creation, listing,
   update and deletion are bound, so links can be minted and never opened.
   The old handler side is small, `internal/httpapi/handler/link_public.go` at
   122 lines over `internal/core/links*.go`, which is about 1,230 lines of
   token lookup, password checking and browse logic.

Taken together the remainder is on the order of five to six thousand lines,
most of it compat. That is a size estimate for planning, not a measurement of
what the rebuild will come to: the engine's dav vocabulary came out at 1,759
lines against 1,641 in the tree it replaces, so a rewrite here has been landing
near parity rather than shrinking.

Then `cmd/stowcloud` and `cmd/sc-smb-agent`, both of which still import
`internal/smbagent`, and `internal/` can go.

## The defects this session found

Each was found by wiring something and watching it, not by reading.

**A revocation that did not revoke.** The three account-facing SMB routes
answered 200 while `lifecycle.Open` passed `auth.New` no renderer and no path.
A nil renderer makes `renderPassdbFile` return immediately, so every credential
change stopped at the database while the sidecar kept authenticating against
the last file anyone had written. A withdrawn password went on working and a
newly set one did not, with the settings screen reporting both as applied. The
previous handoff called this out and it was correct.

**A deployment that could not be set up.** `SetupGate` was written, tested and
constructed nowhere, so nothing minted a token and both setup routes answered
the fallback. The engine could not create a first administrator at all.

**A share created at runtime was never watched.** `startEvents` handed the
watcher every share the registry held at boot, and `adminSharesCreate` handed
it nothing. A share registered while the server ran reported no change under it
until the next restart. Found by a delivery test failing for a share the test
had just created.

**A leaked pin was unobservable.** `Stats` reported only `Registered`, which
cannot show a pin that was never released: `removeSticky` moves the key to the
evictable half rather than unregistering it, so the number does not move.
`Pinned` is reported separately now, and the disconnect test measures it. This
one was found by writing the test for the old hub's known leak and discovering
the assertion could not fail.

**A layer gate with a hole.** `fiberPrefix` was `github.com/gofiber/fiber`, so
`github.com/gofiber/contrib/websocket` matched nothing and would have been
importable from any tier. It matches the organization now.

## What was checked, and how

Every route was driven against a running server through its own tests rather
than by inspection. The three worth naming:

**The change channel, end to end.** A file written on disk with `os.WriteFile`
produced `{"t":"inval","path":"/docs"}` on a real WebSocket. That is the whole
path: inotify, the debounce, the fan-out, the permission recheck, the frame.

**The credential files agree.** Both are rendered from one account list, and
the test reads the uid out of each and compares. They are paired by uid at
import, and a disagreement imports as an empty database with no error anywhere.

**The index survives a restart.** Build, close the engine, reopen the same
directory, and `HasIndex` is true. An index rebuilt on every start would cost
more than the walk it replaces.

## Four tests that passed for the wrong reason

Recording these because each looked correct and proved nothing.

1. **A permission test with no permission.** `TestSubscribingToAnUnreadable
   PathDeliversNothing` passed with *both* permission checks removed: the
   account had no grant, so the path resolved to nothing regardless. The
   property worth testing is revocation after subscribing, which is now
   `TestRevokingAGrantStopsDelivery`, and it does fail when the recheck goes.
2. **A close test that measured a timeout.** The malformed-frame test asserted
   the read failed, which a 5-second deadline satisfies just as well as the
   server closing. It took 5.3s against the mutant and 0.3s clean, which is
   what gave it away. It now asserts the error is not a timeout.
3. **A share-match test where nothing was watched.** Two shares, one
   subscribed: the other emitted no event at all, because a share nobody
   subscribed to carries no kernel watch. Both are subscribed now.
4. **A directory-match test with no subdirectory.** The grant was
   `inherit:false`, so no subdirectory resolved and the subscription was
   refused for a reason unrelated to the test. The fixture grants inherited
   access now.

The shape is the same each time: the assertion was right and the fixture never
reached the code under it. A mutation that survives is the only thing that
finds this, and in three of the four the mutation is what did.

## Surviving mutants, and why

Forty-one mutations across the four commits, thirty-seven caught. The four
survivors are each recorded beside the code they describe:

- **The subscribe permission check** survives alone and is caught when paired
  with the delivery recheck: removing either changes no answer, removing both
  fails. It stays because the two decide different things, and this one
  decides whether to spend a kernel watch on a caller who may not read the
  directory.
- **The per-connection subscription cap** needs a client holding more than a
  thousand resolving paths to reach.
- **The settings read failing** in `openSearchIndex` needs a database that is
  already failing, by which point `Open` has refused for a louder reason.
- **The build failure branch** needs a disk refusing writes mid-traversal.

The first is genuine redundancy; the other three are fixtures costing more than
the line they would cover. Each says so in a comment above it.

The per-commit counts in the commit messages are 17, 8, 10 and 3 caught. The
second of those is wrong by one: the events commit says ten caught of eleven,
and the true figure is nine, because the subscribe check survives on its own
and only the pair is caught. The message cannot be edited; the number here is
the measured one.

## Two things about the harness

**gorilla cannot serve the engine.** It upgrades over `net/http`, and fasthttp
exposes no `Hijacker` for it to take the socket through. `gofiber/contrib/
websocket` is the gorilla API over fasthttp, which is why the wire frames and
the authorization behaviour carried across unchanged. Both entries are in
`deps.allow` with the reason; gorilla leaves with `internal/`.

**A test that only reads a file must not start a listener.** `TestAFirstBoot
PublishesASetupToken` wedged the package in `serve`'s cleanup, which waits on
`ShutdownWithTimeout` and then on the listener goroutine. The test never made a
request, so the listener had nothing to close against. It ran to whatever
`-timeout` the run carried rather than to a bound of its own, which is why it
presented as a hang rather than a failure. Use `lifecycle.Open` directly when
there is nothing to serve.

   method handlers are the largest remaining piece of the rebuild.
2. **The public link surface.**
