# Architecture and Concurrency Audit: 2026-09-04

## 1. Executive Summary

This document records the state of the Stowcloud codebase following the frontend declarative functional programming (FP) refactor, the resolution of raw backend JSON leakage in UI surfaces, and a technical audit of four concurrent backend defect investigations and architectural cloaking mandates.

All frontend automated suites pass (38 test files, 533 unit tests), TypeScript type check reports 0 errors across 478 files, and production static packaging succeeds.

## 2. Frontend Declarative & FP Refactoring (Zustand & Svelte 5)

### 2.1 Core Adapter and Svelte 5 Runes Bridge

The web frontend operates under SvelteKit 5 with runes enabled (`compilerOptions.runes: true`). React store hooks (`useStore`, `useSyncExternalStore`) do not exist in this environment.

- **`web/src/lib/store/core/adapter.ts`**: Implements `toReadableStore(store, selector)`. Svelte's readable store contract requires synchronous invocation of the listener with current state upon registration. `zustand/vanilla` fires `subscribe` only on subsequent mutations, which previously caused undefined initial values under auto-subscription. The adapter executes `fn(selector(store.getState()))` immediately before returning the unsubscribe handle.
- **`web/src/lib/store/core/bridge.svelte.ts`**: Implements `useRunesStore(store, selector)`. Binds a Zustand vanilla store to component lifecycles using Svelte 5 `$state` and `$effect`. The subscription cleanup handle is registered as the effect destructor, ensuring that component unmounting cleans up subscriptions and prevents memory leaks. Raw `setState` is not exposed, preserving the unidirectional action-dispatch boundary.
- **`web/src/lib/store/core/fp.ts`**: Pure data manipulation primitives, including `Result<T, E>` (`ok`, `err`, `isOk`, `isErr`, `mapResult`, `flatMapResult`, `matchResult`), pipeline composition (`pipe`), and immutable collection operations (`setAdd`, `setDelete`, `setToggle`, `setIntersect`, `mapSet`, `mapDelete`, `mapMerge`).

### 2.2 Slices and State Machines

All application state domains have been refactored into pure slices:

1. **Selection (`selection.slice.ts`)**:
   - Pure selection operations (`pureSelectOnly`, `pureToggle`, `pureSelectRange`, `pureSelectAll`, `pureClear`, `pureReconcile`) returning new immutable `ReadonlySet<string>` instances.
   - `selectionReducer` handles all selection mutations. `web/src/lib/state/selection.ts` serves as a backward-compatible adapter delegating to this slice.
2. **Selection Measure (`measure.slice.ts`)**:
   - Manages background directory walk sizing as a finite state machine: `idle`, `measuring`, `done`, `failed`.
   - Debounces walk requests across a 400ms settle window. Pure functions `buildMeasureKey` and `aggregateSizes` handle key comparison and size rollup.
   - Connected to `DetailsPanel.svelte` via `useRunesStore(selectionMeasure.store)`.
3. **Upload Tray (`upload.slice.ts`)**:
   - Decouples worker I/O from state representation. The worker thread communicates events to the main thread, which dispatches pure actions (`QUEUE_ITEM`, `PATCH_ITEM`, `DISMISS_ITEM`, `CLEAR_FINISHED`, `SET_OPEN`) to `uploadReducer`.
   - Immutable array patching via `patchItemInList`. Connected to `UploadTray.svelte` via `useRunesStore(uploadTray.store)`.
4. **Directory Browse (`browse.slice.ts`)**:
   - Implements bounded LRU caching (`MAX_CACHED_ROWS = 2000`) with structural sharing.
   - Pure function `findEvictionVictims` identifies cache eviction targets strictly based on LRU access recency, while guaranteeing that entries present in `selection` are never evicted.
   - `web/src/lib/state/browse.svelte.ts` retains a single `SvelteMap` instance to preserve Svelte 5 reactivity without allocating new 2000-entry maps on every page fetch.
5. **Settings and Modals (`settings.slice.ts`)**:
   - `createDialogStore` provides a typed, pure state machine (`isOpen`, `status: idle | submitting | error | success`, `error: string | null`) for modal dialogs.
   - `validatePasswordChange` provides pure password validation returning `Result<Payload, PasswordValidationError>` with static i18n keys for scanner compatibility.
   - Adopted across `AppPasswordsSection.svelte`, `SmbSection.svelte`, and `TotpSection.svelte`.
6. **Document Editor (`editor.slice.ts`)**:
   - Replaces 11 procedural `$state` variables in `edit/[...path]/+page.svelte` with a unified `EditorSnapshot` and `editorReducer`.
   - Pure functions `isDirty(state)` and `canSave(state)`.
   - Handles document loading, text changes, ETag conditional writes, and `412 fs.precondition` conflicts via action dispatching.

### 2.3 High-Concurrency Real-Time Event Coalescing

Under multi-user concurrency (5 to 1200 concurrent users modifying shared directories), WebSocket `/api/events` delivers bursts of invalidation frames.

- **`createEventCoalescer` (`events.slice.ts`)**: Buffers path invalidations across a 100ms sliding window. Multiple rapid invalidations targeting the same directory are coalesced into a single flush callback.
- **Dynamic Resolution and Session Guard (`events.ts`)**:
  - `this.#wanted` is queried dynamically at flush time rather than at notification time, ensuring that subscribers that unsubscribed during the window do not receive obsolete updates.
  - When a session ends or the socket closes, `this.#coalescer.cancel()` is invoked immediately, and the flush callback explicitly aborts if `authState.screen !== 'browser'`, preventing network requests from firing against dead sessions.

## 3. Backend JSON and Raw Error Leakage Elimination

### 3.1 Problem Analysis

In multiple routes and dialogs, failure handlers directly assigned `err.message` or `failed[0].error?.message` to UI elements (`snackbarMsg`, `loadError`, inline error paragraphs).

Because `ApiError` is constructed from wire JSON responses (`{"error": {"code": "...", "message": "..."}}`), `err.message` contains raw backend text or serialized JSON envelopes rather than localized user-facing copy.

### 3.2 Implemented Fixes

1. **Comprehensive `describeApiError` Application**:
   Replaced all direct `err.message` assignments with `describeApiError(err, fallbackText)`:
   - `web/src/routes/(app)/b/[...path]/+page.svelte`: directory creation, renaming, zip downloads, deletions, transfers.
   - `web/src/routes/(app)/edit/[...path]/+page.svelte`: document load, save, conflict reload, overwrite.
   - `web/src/routes/(app)/trash/+page.svelte`: list load, restore, purge.
   - `web/src/routes/(app)/recent/+page.svelte`: recent list load.
   - `web/src/lib/ui/ShareManageDialog.svelte`: share link listing, creation, editing, revoking.
   - `web/src/routes/emergency/+page.svelte`: safe-mode error messaging.
2. **Batch Item Resolution**:
   In batch deletion (`b/+page.svelte`), replaced raw `failed[0].error?.message` with `batchErrorKey(failed[0].error)`, which maps error codes and detail reason keys to catalogue keys.
3. **Registration in `SERVER_KEYS`**:
   Added all settings validation and lockout reason keys from `go/engine/service/settings/check/check.go` (`settings.would_lock_you_out`, `settings.proxy_range_is_everything`, `settings.out_of_range`, `settings.host_list_empty`, `settings.invalid_host`, `settings.host_role_conflict`, `settings.duplicate_host`, `settings.invalid_origin`, `settings.canonical_url_not_an_app_host`, `settings.path_is_not_a_directory`, `settings.gid_zero_is_root`, `settings.smb_render_failed`, `settings.smb_config_dir_unavailable`, `settings.above_kernel_watch_limit`) to `SERVER_KEYS` in `web/src/lib/api/error-text.ts`.

## 4. Audit of Backend Defect Investigations

### 4.1 Bug 1: Forwarding Header Validation and Client IP Resolution

- **File**: `go/engine/http/middleware/client.go` (`parseAddr`)
- **Status**: Fixed and verified by tests.
- **Mechanism**:
  - `netip.ParseAddrPort` failed when parsing bracketed IPv6 addresses that lacked port numbers (e.g. `[2001:db8::5]`), which standard reverse proxies such as Go's `httputil.ReverseProxy` write into `X-Forwarded-For`.
  - When `parseAddr` failed, `walkForwarded` treated the hop as unparseable and halted traversal, causing the reverse proxy's internal IP to be falsely identified as the client address.
  - The fix adds bracket detection (`len(s) >= 2 && s[0] == '[' && s[len(s)-1] == ']'`) and strips brackets before parsing with `netip.ParseAddr`.
  - Verified by `TestABracketedIPv6HopIsReadWithOrWithoutAPort` and `TestALeftmostPrivateAddressResolvesAsTheClient` in `middleware_test.go`.

### 4.2 Bugs 2 & 3: Multi-User ACL Composition and Download `fs.not_found` JSON

- **File**: `go/engine/service/acl/eval.go` (`evaluateLocked`)
- **Status**: Fixed and verified by tests.
- **Mechanism**:
  - When evaluating access for a user on a folder where both direct user grants and group grants exist, `evaluateLocked` previously invoked `findAllowAny(level, want)`.
  - `findAllowAny` checked only the first matching rule, subtracted its permission bits from `want`, and then exited the level without checking other rules at the same depth.
  - As a result, operations requiring two permission bits (such as `acl.Read` from a user grant and `acl.Download` from a group grant) were denied (`ErrDenied`).
  - In `go/engine/lifecycle/handlers.go`, the `fail()` helper passes errors through `apierr.Classify(err, apierr.VisibilityHidden)`. Under `VisibilityHidden`, any `Denied` outcome is folded into `Hidden` (`fs.not_found`), returning an HTTP 404 response with `{"error": {"code": "fs.not_found", "message": "file not found"}}`.
  - The fix replaces `findAllowAll` and `findAllowAny` with a loop (`for i := range level`) that folds all allowances at that level (`want = want.Remove(level[i].Allow)`), properly composing user and group permissions.
  - Verified by `TestCompositionAcrossDepths` and comprehensive truth-table tests in `eval_test.go`.

### 4.3 Bug 4: Delete Without Permission Breaking Subsequent Downloads

- **Status**: Root cause confirmed to be identical to Bugs 2 and 3.
- **Analysis**:
  - An unauthorized delete attempt fails cleanly at `r.Require(acl.Delete)` and does not mutate filesystem state or trash records.
  - The inability to download the file afterward was caused by the same permission composition defect in `evaluateLocked`: evaluating `acl.Download` failed when download authority depended on composite rules, yielding `fs.not_found`.
  - No separate root cause was observed or verified. The fix in `evaluateLocked` resolves both symptoms.

## 5. Audit of Architectural Directives

### 5.1 Native API Hiding and 404 Cloaking

- **Files**: `go/engine/http/middleware/scope.go` (`Scope`), `go/engine/http/middleware/mount.go` (`scopeHandler`), `go/engine/lifecycle/mount.go` (`writeError`)
- **Status**: Implemented and verified.
- **Mechanism**:
  - Native API routes (`/api/v1/...`) require a browser session cookie (`CredentialSessionCookie`).
  - Unauthenticated requests, requests missing credentials, or requests presenting device credentials (such as app passwords) are rejected by `scopeHandler` with `fiber.NewError(fiber.StatusNotFound)`.
  - The error handler renders this as HTTP 404 with `{"error": "request_failed"}`.
  - External port scanners and dictionary attacks receive identical 404 responses for both non-existent routes and authenticated native endpoints, preventing route discovery.
  - The frontend `http.ts` client recognizes `res.status === 404 && err.code === 'request_failed'` as an expired session and invokes `noteUnauthorized()` to redirect to the login screen.

### 5.2 Compat Layer Isolation

- **Files**: `go/engine/lifecycle/mount.go`, `go/engine/lifecycle/davmount.go`
- **Status**: Implemented and verified.
- **Mechanism**:
  - Nextcloud and WebDAV compatibility endpoints (`/remote.php/dav`, `/ocs`, `/public.php`) and SMB file sharing are mounted outside the native API table.
  - These services perform their own authentication and authorization, allowing device credentials and app passwords to operate on file sync protocols without exposing the internal native administration API.

### 5.3 ACL Grant Storage and Denial Constraints

- **Files**: `go/engine/store/state/sql.go`, `go/engine/store/state/grant.go`
- **Status**: Implemented and verified.
- **Mechanism**:
  - Migration 13 added a unique constraint (`UNIQUE(user_id, share_id, subpath, reach)` and group equivalent), with `foldDuplicateGrants` as a precondition to deduplicate existing records before applying the schema.
  - `PersistGrant` was updated to accept deny-only grants (`Allow: 0, Deny > 0`), enabling administrators to explicitly close off subdirectories inside an otherwise inherited allow grant.
