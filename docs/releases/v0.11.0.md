# Release v0.11.0

The Nextcloud compatibility layer is a rewrite. The previous one adapted the
engine's own WebDAV implementation to the other product's vocabulary through
hooks; this one is a single package that owns that vocabulary outright and
answers every route itself. The reason is the class of failure the old shape
produced: three clients disagree about how a response is parsed, and a shared
renderer cannot satisfy all three, so a fix for one was a risk to another.

## What moved

- `go/engine/http/compat` and the compatibility half of `go/engine/lifecycle`
  are gone. `go/engine/http/nc` replaces both: the OCS envelope, the
  capabilities document, the share wire shape, the DAV property table, the URL
  layouts, the chunked upload collection and the trash collection are all in
  one place, behind the same `compat_nc` build tag as before.
- The engine's own WebDAV mount at `/dav` is untouched and no longer carries
  any of the other product's vocabulary. The vendor hooks it used to be handed
  (chunk headers, vendor properties, the query sources behind `SEARCH` and
  `REPORT`) are removed along with the layer that fed them.
- The device-login service keeps its behaviour and loses its URL literals: the
  spellings now belong to the surface that answers them.

## Fixed by the rewrite

Each of these is something a client does that the previous layer answered in a
way the client could not use.

- **The iOS app listed nothing.** Its parser looks properties up by literal
  prefix, and the shared renderer chose prefixes by sorting namespaces, so
  every response used `D:` for WebDAV and generated names like `ns0:` for the
  vendor namespaces. Every listing parsed as empty. Responses now carry `d`,
  `oc`, `nc`, `s`, `x1` and `x2`, fixed, in every document.
- **Properties went missing on two clients.** One reads only the first
  propstat block of a response and another drops any block whose status is not
  200. The successful set is now always written first, under a 200.
- **Conditional uploads always failed.** The core refuses every validator it is
  handed, by design, because the tokens it mints are derived from metadata. The
  compatibility layer forwarded the client's `If-Match` into it, so every
  desktop upload of a changed file answered 412 and the client restarted the
  transfer. The comparison now happens in this layer, against the token it
  rendered.
- **The favourites screen was empty on one client.** It asks for the starred
  set with a `SEARCH` rather than the filter `REPORT`, and binds the property
  to the vendor's second namespace spelling. Both spellings and both methods
  now answer the same set.
- **A far-future share expiry read as already expired.** A date picker reaches
  years a nanosecond timestamp cannot count to, and the conversion wrapped into
  the past, so the store refused the update. Such a date is now clamped to the
  furthest instant that can be named.
- **Emptying the trash with a read-only credential reported success.** Nothing
  was purged and the answer was 204, so the next listing showed every entry
  back. It is now refused.
- **An account's own access grant appeared in its own share list.** A grant
  that hands the caller their own access is not something they shared, and
  showing it listed the person as a recipient of their own files.
- **An unavailable share was dropped from the root listing.** A folder missing
  from an otherwise successful parent listing means "deleted on the server" to
  a sync client, so a locked container or an unmounted disk would have it
  delete the local copy of everything in that share. Such a share is now
  listed as a collection that cannot be described, which the client reports as
  an error and defers on.
- **One badly named file emptied a whole folder.** A name on a POSIX
  filesystem is a byte string, and a listing carrying a raw invalid sequence
  is not a parseable document, so every client opening that folder saw
  nothing. Found by the new fuzz target over the envelope.

## Verification

- Client-sequence tests under `go/engine/lifecycle`, replaying what the
  Android, iOS and desktop clients send: the browse, upload, download, share
  and device-login flows, including the chunked upload protocol end to end and
  the propstat, prefix, href and identity requirements each client enforces.
- Unit tests in `go/engine/http/nc` over the envelope, the URL layouts and the
  property vocabulary, plus a fuzz target over the value tree that keeps both
  encodings well formed for arbitrary stored text, and over the request
  parsers and the URL layout parser, which read bodies and paths straight off
  the network.
- A live pass against the built binary: device pairing through login flow v2,
  a browse, a download with a range and a conditional request, a plain upload
  with a client-supplied modification time, a chunked upload assembled from two
  parts, and a public link created, listened for, password-protected and
  revoked, with the file fetched by a caller holding no credential.
