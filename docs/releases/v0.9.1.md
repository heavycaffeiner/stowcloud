# Release v0.9.1

One fix, to a regression shipped in v0.9.0.

## Fixes

- **Restart confirmation**: The restart dialog reports a completed restart
  again. v0.9.0 made the health probe report a failing server for any answer it
  could not read, which turned the one signal the wait depends on into its
  opposite: a reverse proxy answers HTML while the process behind it is down,
  and the wait reads a rejection as the outage proving the process went down.
  Resolving it instead meant no outage was ever recorded, so every restart ran
  to its deadline and reported a timeout however well it had gone. An
  unreadable answer fails again, and a body that parses is still accepted
  whatever status carried it, so `503 degraded` remains a real answer.
