# Release v0.12.7

Storing a listen address a pinned process will not use says so.

## The lie moved from the socket to the screen

The previous release pinned the address a process was started with, so a
settings save can no longer move the socket. What it left behind: an
administrator could still edit the bind address on the settings screen, and
the save answered "stored, applied" while the server kept listening
somewhere else. Restarting does not help either, since a restart of this
image re-reads the same argument.

The save now answers stored and not applied, with a finding naming the field
and saying what would apply it: a start without that argument. The value is
still stored, because that start will use it.

Nothing changes for a process that was not given an address. The stored one
still moves the listener when it is saved, and the save still reports itself
applied.

## Verification

Four tests over the real HTTP surface: a pinned process ignores an unrelated
save, an unpinned one moves to a saved address, a pinned one answers a bind
save as stored-not-applied with the finding, and an unpinned one answers the
same save as applied. Removing the finding puts the third back to
`applied:true` with nothing said, which is the state this release fixes.
