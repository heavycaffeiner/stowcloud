# Release v0.12.4

A search the engine turns away says so instead of answering "nothing".

## A busy engine answered an empty list

The engine runs a bounded number of searches at once, four by default, and
refuses the fifth. The compatibility layer dropped that refusal on the floor:
it treated every error from the query as "no results" and answered a
multistatus with no rows, or a unified-search panel with no entries.

To a person that is a search that found nothing. To a sync client it is a
statement that the files are not there, which is the kind of answer a client
acts on. Both surfaces now answer 503 with the reason, which is what a client
retries rather than believes.

This mattered more after the previous releases: an unlimited search runs to
the end with no deadline, so it holds its slot for as long as the tree takes,
and the fifth concurrent search is now a case that happens rather than a
theoretical one.

## Verification

One slot, held by a search parked in its own callback, and then the phone's
own two requests: the DAV SEARCH answers 503 and the unified search answers
503. Removing the fix puts the test back to 207 with an empty body, which is
what it was pinned against.
