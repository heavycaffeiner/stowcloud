# Release v0.20.1

Security update for the core and SMB images, build toolchains, browser dependencies, and Python test tooling.

## Node2Shell: CVE-2026-111497

The previous SMB image contains `brotli-libs 1.2.0-r1` through Samba's GnuTLS dependency. This release requires `brotli-libs >=1.2.1-r0`, which contains the decoder fix. Both Linux AMD64 and ARM64 builds enforce that minimum and inspect the installed package before publication.

The frontend builder and CI use Node.js 24.22.1, including the October 21 security fixes. Node is a build dependency, not the core server's runtime. The core runtime does not contain native Brotli. The Go dependency graph no longer contains `github.com/andybalholm/brotli` after the Huma update.

CISA added CVE-2026-111497 to its Known Exploited Vulnerabilities catalog on October 27. A vulnerable library is present in the previous SMB image, but this audit did not establish a remotely reachable Samba exploitation path. Rebuilds and upgrades are required; changing a Dockerfile does not patch running containers.

## Other security updates

- Go 1.27.3 fixes `crypto/x509` certificate distrust handling, CVE-2026-111943. This affects both the server and SMB control agent.
- `golang.org/x/net v0.62.0` fixes CVE-2026-78661 and CVE-2026-97045. Huma 2.40.0 updates its dependency graph, including the unused alternative HTTP adapters.
- Alpine 3.24.3 and package upgrades replace vulnerable OpenSSL, musl, zlib, Expat, and Python packages in the previous images.
- Vite 7.3.7, Vitest 4.1.12, Undici 8.12.3, source-map-js 1.2.2, and Zod 4.6.7 replace vulnerable frontend build and test dependencies. The standalone browser consumer uses Vite 8.3.5.
- Vanilla Extract CSS 1.21.3 removes the vulnerable `deepmerge` dependency. There is no published fixed `deepmerge` release at the time of this update.
- Python exploration tooling updates requests, urllib3, certifi, idna, pytest, and supporting test dependencies. The dependency floors also apply to CI's pip installation.

The backend temporarily retains `golang.org/x/sys v0.48.0` through an explicit version replacement. Hanami 0.2.0 uses Landlock field names removed in v0.49.0. The retained version has no reported advisory in this audit; the security fixes in x/net remain at v0.62.0.

## Release checks

Container publication now requires a reachable-code Go vulnerability scan and audits of both JavaScript lockfiles. Each image also receives an operating-system package vulnerability scan before publication. The existing native AMD64 and ARM64 build and smoke-test gates remain in place.

The weekly supply-chain workflow now audits both JavaScript lockfiles instead of checking only Go dependencies.

Version-based scanners can still report GO-2026-5932 against the x/crypto module. That advisory concerns the unimported OpenPGP package, has no published fix, and is not a reachable finding from this application. The full module graph also contains the unused `rsc.io/pdf` module with GO-2026-5781 and no published fix. These findings are documented, not suppressed or described as patched.

## Local verification

- Backend full suite passed with Go 1.27.3 and serial package execution. Auth, jail, and bootstrap race tests passed. One listener test returned HTTP 503 during the initial parallel run; the isolated test passed ten repetitions, and the server package and serial full suite passed.
- Frontend: 472 tests passed, along with type checking, linting, formatting, translation checks, bundle budgets, and the production build. Both Chromium smoke tests passed, covering authentication and the file lifecycle.
- Standalone consumers: Go tests and checksum verification passed; browser type checking, build, and its test passed. Both JavaScript dependency audits reported zero findings, including development dependencies.
- Both local AMD64 container builds passed. The SMB image scan reported zero findings. The core image had no OS findings and only the unimported OpenPGP module advisory described above; Go reachability scans were clean.
- Python locked-version advisory checks reported zero findings. The existing environment passed 18 tests; a fresh installation from the updated Python lockfile was not tested.

## Upgrade

Take a stopped backup of durable state, then update both containers:

```sh
docker compose pull
docker compose up -d
```

Version-pinned deployments must select `0.20.1` for both images:

- `ghcr.io/heavycaffeiner/stowcloud:0.20.1`
- `ghcr.io/heavycaffeiner/stowcloud-smb-daemon:0.20.1`

No database migration or storage-format change is introduced relative to v0.20.0. Do not roll back to the vulnerable v0.20.0 images as a security workaround. Source builds require a patched Node release and Go 1.27.3 or newer.
