# Release v0.20.0

This release replaces the Fiber-derived server runtime with Hanami, Fx, Gin, and native `net/http`, and reorganizes the Go implementation around product features, platform services, runtime ownership, and transport adapters.

## Runtime and package architecture

The server now starts through Hanami application bootstrap and Fx composition. Hanami owns process lifecycle, readiness, shutdown, managed listener generations, and Linux security handoff. Gin remains at the HTTP transport edge. Feature, storage, transfer, search, and worker services do not depend on HTTP framework request types.

The previous `go/engine` tree is removed. Product implementation now lives under `go/internal`, split into application composition, feature services, platform services, runtime ownership, HTTP transport, bootstrap, and shared kit packages.

Fiber and fasthttp dependencies, adapters, compatibility helpers, and derived transport code are removed.

## Reusable modules

Stowcloud now consumes released modules without local replacements:

- `github.com/heavycaffeiner/hanami v0.2.0`
- `github.com/heavycaffeiner/hanami/gin v0.2.0`
- `github.com/stowcloud/durablefs v0.1.0`
- `github.com/stowcloud/namesearch v0.1.0`
- `github.com/stowcloud/storage v0.1.0`
- `github.com/stowcloud/transfer v0.2.0`
- `github.com/stowcloud/sandbox-worker v0.1.0`
- `github.com/stowcloud/veracrypt v0.1.2`

Browser content encryption now imports `@stowcloud/rclone-crypt` from the public GitHub `v0.1.0` tag pinned to commit `eb48c44602f568a783b5b7aa34c02ee7ea55b09d`. The package is not yet available through npm; the Git tag is the distribution source until registry publication is possible.

Search keeps Stowcloud-specific VFS, authorization, live-stat filtering, product limits, HTTP, SSE, and Nextcloud behavior in this repository. The published namesearch module owns the storage-neutral query and index contracts.

## Upgrade and rollback

The state database gains schema version 20 for direct-transfer publication receipts. The migration preserves existing account, share, upload-session, and file records, but a v0.19.1 binary refuses to open a version-20 state database. Other persistent formats remain unchanged.

For rollback, stop the new server and restore a complete pre-upgrade snapshot before starting v0.19.1. A binary swap without restoring the schema-19 snapshot does not work. Preserve the data directory, share data, and SMB rendered configuration. Do not copy the runtime SMB control socket. Confirm that uploads or other writes accepted after the snapshot are reconciled before restoring it, or they will be lost.

Security policy changes still require an external process replacement because an installed Landlock domain cannot be widened in place.

## Verification

The repository gate covers Linux AMD64 and ARM64 builds, non-Linux build tags, vet, lint, regular and compatibility tests, the race detector, vulnerability scanning, the frontend build, embedded UI checks, and browser interaction. Container CI builds and smokes the core and SMB images for AMD64 and ARM64.

## Container images

The release workflow builds and smokes the core and SMB images on Linux AMD64 and ARM64. Once the release tag passes, it publishes `ghcr.io/heavycaffeiner/stowcloud:0.20.0` and `ghcr.io/heavycaffeiner/stowcloud-smb-daemon:0.20.0`.

Existing Compose deployments can update with `docker compose pull` followed by `docker compose up -d` after taking a stopped durable-state backup.
