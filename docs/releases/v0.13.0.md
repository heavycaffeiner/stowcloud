# Release v0.13.0

A security, integrity and interface remediation. Three audits of the working
tree, recorded under `docs/internal/audits/`, produced 11 security findings, 20
logic findings and 19 interface findings; every one of them is closed here,
along with what surfaced while closing them.

## Authority follows the operation, not the parent

A public link over a folder used to carry the folder's permission set into
every descendant, so a file the link's creator could not read was readable
through their link. Descendants are now resolved against the creator's own
effective authority at each step, and a recursive copy resolves the source and
the destination for each child rather than cloning the parent's bits.

Compatibility link management applies a restricted app password's permission
mask and share allowlist, and the native DAV root lists only the shares such a
credential may reach. An upload-only link no longer reports the name, kind and
size of a guessed descendant.

## Uploaded bytes never run as the application

Every route that serves file bytes shares one policy: a browser-executable
type (HTML, SVG, XML, JavaScript) is forced to download, and anything served
inline carries a sandboxing content security policy. The native DAV mount and
the compatibility DAV mount did not have it and now do.

The two host roles are enforced rather than only classified. A deployment that
names a content host serves the compatibility direct stream there and nothing
else: the API, the interface, the DAV mounts and the public link surface
answer 421 on that name. Once a content host is named, the app host refuses
the direct stream, and a minted direct link names the content host on the
request's scheme and port.

## Login binds to the origin that received it

A password or factor sign-in has to carry an Origin that matches the request's
scheme and authority exactly, whether or not a session cookie is already
present, and its body has to be JSON. A cross-site form can no longer install a
session in a visitor's browser. Comparison normalizes case, default ports and
IPv6 authorities, and honours the scheme a trusted proxy reports.

Emergency recovery authenticates the password once, tries the authenticator
code before a recovery code, spends one limiter attempt and creates one
session.

## Compatibility CORS follows the allowlist

OCS responses used to answer every origin with a wildcard. They now answer
only an origin listed in `allowed_origins`, echoed with `Vary: Origin` and
never with credentials; any other origin, and a request that carries none,
receives no cross-origin headers. A browser-hosted client that relied on the
wildcard needs its origin listed. `compat_canonical_url` is the base URL
rendered for a request that carries no host.

## Encryption keys live as long as the operation

Locking a share while a file was still being read could leave that file
encrypted with an all-zero key. Each encryption now owns a copy of its key,
notices a session change under it and clears the copy afterwards. An encrypted
upload resumes only the exact ciphertext its session was opened for; a browser
prepares one whole-file ciphertext at a time and holds it only until the
worker releases it.

## Uploads publish what they accepted

A retry of an already accepted chunk with different bytes was refused and yet
published. Replacement chunks are validated before they touch committed
ranges. A failed finalization returns to a repairable, expiring state instead
of one nothing can write to or collect. A zero-byte upload is published before
the browser reports it done. Resume identity includes the destination and the
relative path, the worker's pause, cancel and retry commands are owned by the
plan generation they were issued against, and a cancellation the server could
not confirm is kept as uncertain rather than forgotten.

An object-store copy that answers an error document inside a 200 is no longer
treated as committed, and a redirect that would downgrade HTTPS is refused.
Replacing a directory validates and stages the work before the old tree goes.
Copies, drops, trash, moves and both upload modes reserve and settle quota the
same way.

## Search says what it did not cover

An interrupted or event-starved name index stays marked incomplete instead of
answering as the whole corpus. A walk that hits its deadline keeps the hits it
collected and says its depth was cut. Indexed search filters by permission and
kind before it applies the result limit, so a denied candidate cannot starve
the page.

## Archives and listings tell the truth

A bounded archive carries a collision-free incomplete marker rather than a
valid zip that silently omits members. A recursive DAV listing keeps every
ancestor segment in each href. The compatibility direct stream closed its file
before the body was written and sent it chunked under a Content-Length, so
every fetch ended in a truncated transfer; it now streams with its size. The
ids a compatibility listing or write reports are recorded, so a preview or a
direct link asked for by id alone answers the file rather than 404.

## The interface keeps your work

Leaving the editor with unsaved text offers Stay, Discard and Save rather than
dropping the draft. A partly failed batch keeps the outcomes that succeeded and
offers the failed set for retry. A settings save preserves the other sections'
unsaved edits, and a refetch does not overwrite typing. Setup reports the
account and the first share separately and reuses its sign-in across a share
retry. One-time secrets stay visible until acknowledged, including when the
clipboard is denied.

The preview traps focus and restores it. The tree pages late children and
reaches them by keyboard. Fields associate their errors and menus expose their
keyboard semantics. The file workspace has a current-folder heading and one
New command. Every authenticated route shares the navigation and a visible
global search that states its boundary. Touch opens a row while its checkbox
selects it. Personal and administrative settings are grouped by task and
ownership. Public recipients can retry a failed load or upload in place.

## Verification

Focused regressions for each finding, `go test ./...` in both build modes, the
race detector over upload, search and core, the frontend type check with zero
errors, 47 frontend test files and 528 tests, localization validation, the
production build, the bundle-size budgets and the repository gate. Driven in a
browser: the editor draft guard, the directory refusal, the links overview
without per-row requests, setup field labels and the compact layout.

Not exercised: a live identity provider, SMB and WebDAV clients, an object
store, process kills, disk faults, screen readers and physical devices. The
audits under `docs/internal/audits/` record what each claim rests on.
