# Release v0.12.10

Two terminal states were wrong about what the work had done.

## An interruption reset the count it kept

`InterruptOp` documented that it keeps an operation's progress and then wrote
zero into the column. A client re-attaching read a build that had indexed most
of a corpus as one that indexed nothing, and the row held nothing to recover
the real figure from. The statement no longer touches progress.

## An index build reported done however it stopped

Every exit without an error recorded done. A build an operator cancelled, and
a build the shutdown stopped, both reported a complete index over a partial
one, which left nobody a reason to run it again. The outcome now names why it
stopped: interrupted for a shutdown, cancelled for an operator, done for a
walk that reached the end or its own corpus bound. The count it reached is
recorded either way.

## Verification

Three tests drive the build's outcome directly: stopped by a shutdown reads
interrupted, cancelled reads cancelled, untouched reads done with the file
count it indexed. The first two fail against the single done path. A state
test pins the progress an interruption keeps and fails against the statement
that zeroed it.
