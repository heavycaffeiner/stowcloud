# Release v0.12.3

The index estimate counts what the index now holds.

## The estimate was sized against files alone

Folders were added to the index in the last release, and the estimator that
sizes it before an administrator builds it was not: it descended through a
directory without counting its name or folding it into the trigram sketch.
Every folder name was therefore missing from the predicted size and build
time, and a tree of many small folders was under-reported by more than a
rounding error.

The scan now measures a folder exactly as the build indexes one, so the
estimate and the artefact describe the same corpus. The build's own progress
counter, the one the ceiling is measured against, counts names of both
kinds; that is now stated where the counter is declared rather than implied
by its name.

The admin screen said "search file names"; it says names, which is what a
search now matches.

## Verification

The scan and the walk are compared entry for entry over the same tree, which
is what caught the mismatch: the scan counted 5 where the walk found 3.
Both now agree, folders included, and the permission test agrees on the pair
a refused folder hides.
