The server is a new codebase. Every route, the storage layer, the sandbox and
the WebDAV surface were rebuilt as `go/engine`, and the interface was rewired
onto it. This release is that work.

**The image names and tags changed.** Update your compose file before pulling:

```
ghcr.io/heavycaffeiner/stowcloud:stable
ghcr.io/heavycaffeiner/stowcloud-smb-daemon:stable
```

The sidecar is its own package now rather than a tag prefix on the first, and
the channel is a plain tag: `:stable`, `:latest` as its alias, `:nightly` for
master, and `:0.5.0` to pin this release. The old `:core-*` and `:smb-*` tags
are gone along with the images they named.

Both are manifest lists covering amd64 and arm64, and every architecture was
built and run on its own hardware in CI before publishing.

## What changed

**The whole backend.** The old `go/internal` tree is gone. The engine splits
into layers that cannot import each other backwards: `store` owns the
databases, `service` owns the domain, `http` owns the routes, and `lifecycle`
assembles them. A gate in CI fails the build if that ordering is violated.

**Path handling is three types, not one string.** A URL path, a
share-relative path and a host path can no longer be passed to each other by
accident. Every resolution runs against the share root's own descriptor, so a
symlink cannot walk out of the share it lives in.

**The sandbox covers what the server touches and nothing else.** A Landlock
domain is installed before the first file is opened, naming the data
directory and each share's parent. The parent rather than the share itself,
so a folder added from the admin screen works without a restart.

**WebDAV grew the pieces sync clients actually use.** RFC 5323 `SEARCH`,
the filter-files `REPORT`, chunked uploads wired to the resumable engine, and
the vendor properties a client reads on every `PROPFIND`. The compatibility
layer is compiled behind a build tag and is isolated from the engine by an
import-graph gate.

**Settings live in the database.** There is no configuration file to edit.
`sc-engine settings get` and `settings set` read and write the same store the
admin screen does, for a deployment whose stored configuration stops the
server answering.

**The SMB sidecar is not optional to start.** It comes up with the stack and
sits idle; the daemon runs only while SMB is on in the admin screen, which the
agent picks up over the shared socket. It used to sit behind a compose
profile, which meant the switch in the interface did nothing until somebody
also brought a second container up from a shell.

**An app password reaches the files and nothing else.** The route table has
always said the account and authentication families are session-only: a
credential handed to a device must not be able to mint another one, read the
session list or revoke the session that created it. The check that enforces
it ran against metadata attached too late to read, so it passed everything.
It runs now. A sync client is unaffected, because the file surfaces are what
it uses; anything driving the account routes with an app password will start
receiving 401 and should use a session.

**The first-run screen finishes in one click.** Setting a server up left the
person on an empty panel, and pressing the button again answered 403 on a
login the screen had no way to satisfy. Three separate wire contracts were
described in the client as shapes no response has ever carried: the login
result, the setup findings, and a pass marker that was being counted as a
warning worth stopping for. A TOTP account could not finish signing in at
all. The types now describe what the server sends, and the mock answers in
those shapes rather than in the ones the types invented.

**Adding a folder share works.** The screen sent `host_path` and the handler
decodes `host`, and the decoder refuses a field it does not know, so every
attempt answered 400 with nothing on screen naming the field. The same
mismatch was in the first-run form's optional share, which made naming one
there fail the whole setup. The contract check now compares request bodies
as well as responses, so a name that only one side knows fails the build
rather than a button press.

**Editing a share link works, and can only narrow it.** The edit dialog always
sends the permission set, which the handler did not decode, so every edit was
refused: changing a label or an expiry failed too. The field is decoded now,
and a patch may only reduce what the link grants. Widening is refused rather
than quietly dropped, so a URL already handed out cannot become an upload
endpoint, and a permission the owner has since lost cannot be restored through
an edit.

## Upgrading

This is a rewrite. A 0.3.x data directory has not been migration-tested
against it, and the safe path is a fresh data directory: create the
administrator again through the setup screen and re-add your shares. Your
files are untouched by any of this; they live in the folders you mounted.

If you want to try upgrading in place, copy the data directory first.
