# Release v0.19.1

This patch keeps folder permission dialogs open while a shared folder is selected and after the new permission is added.

## Web interface

Selecting an item from a Material select no longer closes its parent dialog. The dropdown emitted a bubbling `close` event, and the dialog treated that descendant event as its own close request. The shared select now contains its internal close event, and the shared dialog handles only close events from the dialog itself.

Nested permission dialogs now close independently. Adding a folder permission closes the add form while leaving the user's or group's permission list open.

The fix applies to every shared select, including folder permissions, group membership, share backends, share link settings, and the emergency settings section picker. The account, search sort, desktop menu, and compact menu implementations were also checked for the same event collision.

## Release validation

The browser regression suite now exercises the complete folder permission flow, including choosing a non-default share and creating the grant. Browser test startup also waits for Chrome's debugging endpoint and installs the agentic test dependencies explicitly.

## Container images

The core and SMB images are published for Linux AMD64 and ARM64:

- `ghcr.io/heavycaffeiner/stowcloud:0.19.1`
- `ghcr.io/heavycaffeiner/stowcloud-smb-daemon:0.19.1`

The `stable` and `latest` tags point to this release. Existing Compose deployments using those tags can update with `docker compose pull` followed by `docker compose up -d`.
