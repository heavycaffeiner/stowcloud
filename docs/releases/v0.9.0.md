# Release v0.9.0

A share is no longer only a directory on the server's disk. It can be an S3
bucket or a VeraCrypt container, and its contents can be encrypted so that the
server never holds the key. Single sign-on works. Alongside those, this release
carries the fixes written up for v0.8.3, which was never cut.

## Features

- **Object storage and encrypted containers as shares**: A share can be backed
  by an S3 bucket or a VeraCrypt container instead of a host directory. Both
  backends are implemented in-process in pure Go, with no helper binary, no new
  dependency and no mount: the engine's seccomp filter refuses `mount`, the
  shipped image drops every capability, and the filesystem admission gate
  refuses FUSE because inode identity cannot be shown to survive a remount.
- **End-to-end share encryption**: A share can be marked encrypted. The server
  stores the scheme name, the salt and a verifier, and nothing else; it holds no
  passphrase and no key and cannot read a byte of what is written. The format is
  rclone's own crypt, so the same share can be mounted with rclone and read
  outside the browser. The toggle is refused in either direction unless the
  share is empty, counting the trash as well.
- **The whole of VeraCrypt's format**: All five ciphers, all ten cascades, all
  five PBKDF2 hashes, Argon2id, a PIM and a hidden volume. Serpent, Camellia,
  Kuznyechik, Whirlpool and Streebog are in-tree, each verified against its
  standard's published vectors. FAT12, FAT16 and exFAT are read as well as
  FAT32, with the FAT type decided by cluster count rather than the BPB's
  frequently wrong type string.
- **Single sign-on**: The OIDC callback redirects on every outcome instead of
  answering a JSON document into a top-level browser navigation, and the
  sign-in table no longer carries a foreign key that an unauthenticated flow
  could never satisfy. A public client with PKCE is supported, the redirect URIs
  are shown on the admin screen, and post-logout and RP-initiated logout are
  wired.
- **Share occupancy**: A share reports whether it holds anything, which is what
  lets the encryption toggle refuse safely and what the admin screen reads
  before offering it.

## Fixes

- **Trash isolation**: Trash listing, restore, and purge evaluate permissions on
  the entry's original path instead of the caller's root, so a subfolder-scoped
  grant can no longer read or delete another subfolder's trashed entries.
- **Home directory cleanup**: Deleting an account removes its home directory, so
  a newly created account reusing the same name no longer inherits the previous
  account's files.
- **Drop link limits**: Public drop links enforce the request body limit and
  charge storage quota instead of accepting unbounded payloads in memory.
- **Audit retention**: Audit entries are pruned against a retention policy, and
  cursor pagination stays correct on sparse queries.
- **Listing performance**: Directory listings and walks drop redundant stat calls
  and repeated permission evaluations, and upload chunk handlers stream request
  bodies instead of buffering them on the heap.
- **Permission errors**: An action refused by an access rule on a folder the
  account can already see answers 403 with `fs.denied` rather than 404, and the
  interface renders it as "No permission" for uploads, deletes, moves, copies,
  folder creation, renames, trash operations and folder size measurement.
- **Upload refusals**: A 403 during upload session creation or chunk transfer
  stops the transfer immediately and names the permission refusal, instead of
  consuming the retry budget and reporting "out of retries".
- **SMB password after disabling two-factor**: Turning two-factor authentication
  off restores the account password as the SMB credential. Previously the
  credential row deleted at enrollment was never recreated, so SMB stayed
  unusable and the settings screen kept reporting no credential.
- **SMB credential restored on sign-in**: An account eligible for SMB and
  holding no credential gets one sealed from the password it just signed in
  with. An account with a second factor enrolled is left alone, which keeps the
  account password from bypassing that factor.
- **SMB daemon health**: The admin screen reports what the sidecar actually did.
  A daemon that exits on every start because it cannot bind its port is reported
  as failed rather than as started, and an absent list no longer arrives as
  `null` and takes the server settings screen down while rendering.
- **Client address behind a proxy**: A peer that is not itself on the internet,
  which is what a tunnel daemon or sidecar proxy is, is trusted with no
  configuration, so the audit log and the login rate limit record the address it
  forwards. A configured trusted-proxy list still decides on its own, and a
  caller arriving straight off the internet is never believed.
- **Text editor saves**: Saving works. Every save sent an `If-Match` condition
  against a metadata-derived change token the server refuses by design. The
  editor now compares the token it loaded against a fresh one taken at save time
  and offers the conflict choice only when the file really moved.
- **Actions the grant forbids**: The listing reports what the account may do to
  the folder itself and the interface reads it, so upload, "new folder", rename,
  delete, download, duplicate and share appear only where they are permitted.
  The destination picker names a folder the account cannot write to and keeps
  both transfer buttons disabled.
- **Refusal messages**: The wire codes the interface translated had drifted from
  the ones the server sends, so a refused save, a full disk, an unusable name and
  a locked item all rendered as a generic fallback.
- **Upload tray**: A tray with nothing in flight reported "Upload done" whatever
  its rows said. It now reports how many failed, and a failed row can be cleared.
- **Search index build**: Starting a build reported that it could not start while
  the build was in fact running, because the response was read for a field no
  route sends. The build now appears in the tray and runs to completion.
- **Folder sizes after an outside change**: A write that did not come through
  this server invalidates the cached rollup for that directory and its parents,
  so a folder full of files no longer reports a total size of zero for as long
  as the process runs.
- **Restart dialog**: The dialog reports a restart only once it has observed the
  process go down and answer again, rather than reading a health result left
  over from before the restart was asked for.
- **Admin log source switch**: Switching the log source takes effect.
- **App passwords**: A credential revoked by a wipe request reads as expired
  instead of live, and an expiry in days is bounded so it cannot overflow into a
  perpetual credential.
- **Image provenance**: A published image is refused when the binary inside it
  was built from a commit other than the one the label names. A cached layer
  under a fresh label previously shipped as though it were current.
- **Counted strings**: Every counted string has a singular form, so a count of
  one no longer reads "1 items".
- **Phone layout**: The admin share screen fits a phone, and a row no longer
  tints at the same time as the control under the pointer.
