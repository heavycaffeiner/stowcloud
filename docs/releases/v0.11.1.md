# Release v0.11.1

One fix. Uploads from the phone app failed with "method not allowed", and no
byte of the file was ever sent.

## The fix

- **A folder answered a read as a method it does not allow.** Before it sends
  anything, the app probes the target folder with `HEAD` and accepts only 200,
  401 or 403. A collection has no body to send, so this surface refused the
  method, and the app reported the refusal and abandoned the transfer. The
  probe now answers 200 with the folder's own headers and no body, which is
  what the client is asking for: does this folder exist and may I write to it.

The upload itself was never the problem, which is why it was not caught: the
`PUT` that follows the probe worked, and every upload test drove that `PUT`
directly. The probe is now part of the upload test, in the order the client
runs it.
