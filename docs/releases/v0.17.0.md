# Release v0.17.0

This release emits the setup token in the container startup log, repairs media search content type handling in the Nextcloud compatibility layer, and migrates search indexes through durable storage.

## Initial setup

The first-run setup token is now logged to standard error on server startup. Operators can retrieve the token directly from `docker compose logs sc` instead of reading the file through `docker compose exec`.

Writing the setup token file to the data directory is now non-fatal. If host volume permissions prevent creating the file, the server still boots and reports the token in the log.

## Nextcloud compatibility

The Nextcloud compatibility layer now honors the requested content type when searching for media items. Clients filtering search queries by audio, image, or video types receive only matching results.

## Search indexing

Index migrations now use durable atomic replacement. Interrupted or shadowed migrations no longer leave partial index directories behind.

## Governance and issue forms

GitHub issue creation now uses structured forms for bug reports, feature proposals, and usage questions. Blank issues are disabled and incoming external pull requests are closed automatically in favor of issue discussions.

## Container images

The core and SMB images are published for Linux AMD64 and ARM64:

- `ghcr.io/heavycaffeiner/stowcloud:0.17.0`
- `ghcr.io/heavycaffeiner/stowcloud-smb-daemon:0.17.0`

The `stable` and `latest` tags point to this release. Existing Compose deployments using those tags can update with `docker compose pull` followed by `docker compose up -d`.
