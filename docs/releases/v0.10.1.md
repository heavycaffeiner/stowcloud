# Release v0.10.1

Fixes to the share link screen shipped in v0.10.0, and a documented limit on
where a sync client may upload.

## Fixes

- **Share link paths**: A link listing reported the path as it is stored, which
  carries the subpath of the grant it was made under. An account granted one
  folder inside a share sees that folder as its own root, so the stored path
  begins with a component that account never addresses, and every navigation
  from the links screen landed somewhere that does not exist. The listing now
  reports the path the account's own client uses.
- **A link with no token took down the share screen in the app**: The listing
  describes a link by its token, and the Nextcloud client reads that token for
  every link entry without checking whether it is there. The failure that
  produces is not caught anywhere in its parser, so the whole share screen
  reports that it could not load, against an HTTP 200. One link whose token
  cannot be recovered therefore cost the entire listing. Such a link is now
  left out, so the rest still shows.
- **Link management from the overview**: A link published by another account
  opened an editor that could show nothing and change nothing, because the API
  refuses an edit or a revoke from anyone but the owner. Those rows are now
  read-only, and still reachable by keyboard with a label saying why. Revoking
  a link refreshes the administrative overview as well as the owner's own.

## Changes

- **The share link overview is web-only**: v0.10.0 added an administrative
  variant of the app's share listing. It cannot work: an overview crossing
  accounts must not hand an administrator every visitor's access, so it has to
  blank the tokens, and a blanked token is exactly what breaks the app's share
  screen. The overview stays on the web interface, where it needs no token to
  be useful. The app continues to list an account's own links.
- **Links moved out of the navigation bar**: It sits in the navigation drawer.
  The bar and the rail hold three to five destinations and an administrator had
  six.

## Known limits

- **Sync clients upload into a share, not the account root**: This server's
  root is the list of shares an account was granted rather than a folder, so an
  upload aimed at it answers 404. In the mobile app, set the auto-upload folder
  to a path inside a share, such as `/Photos/Camera`, and pick a folder inside
  a share when uploading by hand. Uploads into a share work throughout,
  including resumable transfers of any size.
