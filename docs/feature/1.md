# Phase 1: FS abstraction gaps

## Goal

Close the small gaps left in `go/internal/vfs` that phase 2 relies on. This is
a thin phase: most of what the requirement calls the FS abstraction layer
already exists.

## Current state

Already implemented, no work needed:

- Openat2-rooted `ShareRoot` with read, durable write (`WriteDurable`,
  `PublishPart`), copy (`CopyRange` with copy_file_range and a buffered
  fallback), rename and delete; `core/ops.go` builds Copy, Move and Delete on
  top.
- Free-space probe: `ShareRoot.Space(p)` answers `FsSpace{Total, Free,
  Available}` via fstatfs on the resolved directory handle.
- Volume identity: `ShareRoot.Dev()` and `Stat.Dev` exist, and `core.Move`
  already picks rename versus copy-and-delete by comparing them, not by
  trying rename and reading EXDEV.

## Status

Done. `ShareRoot.DirDev`, `ShareRoot.resolveDirOrParent` and `spaceOf` in
`go/internal/vfs/root.go`, `File.Space` in `go/internal/vfs/file.go`,
`crossesDevice` rewritten in `go/internal/core/ops.go`. Tests:
`go/internal/vfs/space_linux_test.go` and
`go/internal/core/move_nestedmount_linux_test.go`.

## The actual gaps

1. **Nested-mount move decision.** `core.Move` compares the source entry's
   `Stat.Dev` against the destination share root's `Dev()`. When the
   destination directory is a mount nested inside the share (a RAID volume
   under `media/`), the root's device is the wrong answer and a same-device
   rename is attempted across a real boundary. Fix: stat the destination's
   parent directory and compare against that device.
2. **Space on an open file.** Phase 2's budget check runs against the cache
   spool while holding a `*File`. Add `File.Space()` (fstatfs on the handle),
   so the probe does not re-resolve a path it already holds open. The device
   is already there: `File.Stat().Dev` comes off the same descriptor.

## Acceptance criteria

- A move whose destination directory is a different device than its share
  root copies instead of failing, covered by a test with a tmpfs mounted
  inside a share.
- `File.Space()` agrees with `ShareRoot.Space()` for the same directory.
- No behavior change for any other caller.

## Out of scope

- Any upload-engine change (phase 2).
- Restructuring the vfs/core split.
