# Search 01: the index format

> This document describes a from-scratch rebuild. The existing code under
> `go/internal/search/index` is referenced as a behavioral specification
> only. The new implementation is written completely from scratch;
> nothing is copied.

## The position

The trigram name index is **off by default, an escalation, and a
cache**: delete the directory and search keeps working on the walk tier.
No durable truth lives here; everything in it is rebuildable from the
shares.

## Layout

```
<store>/names/
  base.idx        immutable, block-compressed
  delta.NNN.idx   append-only, lightly compressed, linearly scanned
  tomb.idx        deletions
```

A query is base plus the deltas minus the tombstones. The split is a
necessity, not an optimization: an immutable block index cannot be
upserted (a name cannot land inside a compressed 32-name block, a block
id cannot land inside a delta-encoded posting list). plocate sidesteps
this with a nightly rebuild; this index cannot, because changes must be
visible immediately. So writes go to a delta segment in constant time
and the rebuild happens under a gate, at idle, when the deltas pass
`MergeRatio`.

## Durability

Verified in the old code and normative here:

- `base.idx` and `tomb.idx` publish through the durable atomic replace
  (now `store/fsatomic`; the survey's repoint).
- Delta segments are `O_APPEND` writes with an fsync before close;
  write and close errors join, never a swallowed close.
- Every segment carries a corruption checksum (`FNV1a32`); a bit flip
  stops the scan rather than serving garbage. Recovery
  (`ReadRecords` -> `TruncateTo`) drops the torn tail of a delta and
  keeps what verified.

## Tuning

```go
type Config struct {
    BlockSize    uint32  // 32, plocate's default and this one's
    PruneDFRatio float32 // 0.6: drop a trigram in more blocks than this
    MergeRatio   float32 // 0.15: rebuild when deltas grow past this
}
```

`BlockSize` trades compression and posting-list length against posting
precision; `FalsePositiveBlocks` in the result is the number that says
whether the block size suits the corpus.

## The query contract

```go
const MinTrigramQuery = 3

type Hit struct{ Share uint32; Path, Name string; Score float32 }

type Result struct {
    Hits     []Hit
    Fallback FallbackReason
    CandidateBlocks, ScannedEntries, FalsePositiveBlocks int
}
func (r Result) MustFallBack() bool
```

**The fallback is a field, never an empty slice**, because "the index
looked and found nothing" and "the index declined to look" are different
answers, and conflating them turns a fallback into a wrong empty result.
The reasons:

| Reason | Meaning |
| --- | --- |
| `FallbackQueryTooShort` | under three bytes: no trigram exists |
| `FallbackAllTrigramsPruned` | every trigram was high-df pruned; the intersection would be over nothing |
| `FallbackIncomplete` | the index reached its entry ceiling and is knowingly short of the corpus |

`FallbackIncomplete` carries its own history: without it an incomplete
index answers from what it has, and a file past the ceiling is absent
from a result carrying a success status, silent shortness by another
route.

**The index stores names only.** A hit's size and time come from a stat
the caller performs after its own ACL check, which doubles as the
staleness check. This is the boundary that keeps index rows untrusted:
nothing read from disk here reaches a client without revalidation
against the live filesystem (02's `pathUnder` invariant).

## Deliberate changes

1. **Trigram sort/dedup come from the root package** (the one-home rule,
   00). This package already imports it for `Trigram`, `Varint`, `Fold`.
2. **The hand-written `min` dies**; the builtin serves.
3. **The durable replace repoints at `store/fsatomic`.**

The format, the checksums, the tuning defaults, the fallback taxonomy
and the recovery behavior are unchanged; the golden and fuzz corpora
carry over as fixtures (regenerated by the new writer, compared
behaviorally, since the format is preserved).

## Tests

- Round-trip: build a base from a corpus, query it, get the corpus back;
  the golden block/payload encodings.
- Fuzz: `OpenBase`, `DecodeBlock`, `DecodePayload`, `ReadRecords`,
  `Ascending` never panic on arbitrary bytes.
- A bit flip anywhere in a segment stops the scan (the checksum test).
- A torn delta tail is truncated and the prefix survives (crash
  recovery).
- A block id past the count refuses.
- High-df pruning: a trigram over the ratio is dropped and the query
  falls back rather than intersecting nothing.
- The ceiling: an index at capacity reports `FallbackIncomplete`, not a
  short success.
- Merge: deltas past the ratio fold into a new base under the gate;
  concurrent queries during a merge see either the old or the new set,
  never a mix (the old concurrent-merge test, rebuilt).
- Tombstones: a deleted name stops matching before the merge lands.
