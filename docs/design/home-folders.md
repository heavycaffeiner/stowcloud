# Home 폴더와 SMB 접근

Home은 서버가 자동으로 관리하는 개인 공간이다. 공동 공간의 공유 폴더 권한과 별도로 제공된다.

## 계정 생성과 관리

| Home 설정 | 사용자 생성 화면 | 추가 공유 폴더 권한 |
| --- | --- | --- |
| 켜짐 | 개인 폴더가 자동 제공된다고 안내하고 생성 완료 상태를 표시 | 선택 사항. 공동 폴더가 필요할 때 추가 |
| 꺼짐 | 사용자 또는 소속 그룹의 공유 폴더 권한이 필요하다고 안내 | 생성 후 권한 창을 열어 설정 지원 |

계정 생성이 완료되면 SMB 게시 전에 개인 디렉터리와 자동 권한을 준비한다. Home을 켜거나 서버를 시작할 때 기존 계정도 준비한다. 준비에 실패해도 계정을 다시 만들 필요는 없다. 사용자 목록과 폴더 권한 화면에 준비 상태를 표시하며, 관리자가 경로·권한 문제를 해결한 뒤 재시도할 수 있다.

계정 삭제 후 같은 이름이나 ID가 다시 사용되어도 이전 파일을 새 계정에 넘기지 않는다. 기존 자동 권한이 없는 디렉터리에 파일이 남아 있다면 Home 준비를 거부한다. 관리자가 잔존 디렉터리를 별도로 옮긴 뒤 재시도할 수 있다. 생성 중 중단된 빈 디렉터리는 재사용할 수 있다.

계정·그룹 삭제로 데이터베이스에서 함께 제거된 권한도 메모리의 권한 평가기에 즉시 반영한다. 재사용된 ID에 이전 Home·공유 폴더 권한이 남지 않도록 한다.

권한 화면의 Home은 `개인 공간 · 자동 관리` 항목으로 표시한다. 일반 공유 폴더의 추가·수정·삭제 대상에서 제외하고 서버의 Home 설정으로 연결한다. API에서도 Home 공유, 권한, 암호화 설정의 수동 변경을 차단한다. 관리자 초기 권한 부여는 공통 Home 트리를 포함하지 않는다. 기존 설치에 남아 있는 공통·그룹·다른 계정 경로의 Home 권한은 활성화 시 제거한다.

## SMB 개인 폴더

웹에서는 `Home`, SMB에서는 사용자별 전용 주소를 제공한다. 예를 들어 Alice의 주소는 `\\nas\Home-alice`이며, 공유 루트는 Alice의 실제 개인 디렉터리다.

- 각 공유의 인증 허용·쓰기 목록에는 소유자 한 명만 포함한다.
- 개인 공유는 공유 목록 탐색에서 숨긴다. 사용자가 본인의 설정 → 연결 화면에서 정확한 주소를 확인하고 복사한다.
- 개인 공유는 심볼릭 링크를 따라가지 않는다. 개인 디렉터리 자체가 링크이거나 아직 준비되지 않았다면 게시하지 않는다.
- 공통 Home 저장 루트는 SMB에 게시하지 않는다. 일반 공유 폴더의 전체 경로 권한을 넓혀 Home을 게시하지 않는다.
- 기존 숫자 ID 이름의 디렉터리는 저장된 권한 경로를 그대로 사용한다. 로그인 이름으로 새 디렉터리를 만들어 기존 데이터와 분리하지 않는다.
- 기존 일반 공유 이름이 `Home-alice`와 충돌하면 개인 공유에 고유한 접미사를 붙인다. 새 일반 공유에는 Home 전용 이름을 사용하지 못한다.

고정 경로와 소유자 목록을 게시하므로 공통 서비스 계정으로 파일 작업을 수행하는 Samba 설정에서도 사용자 이름 치환에 의존하지 않는다. Samba의 `%U`, `%u`, `force user`의 차이는 [공식 설정 문서](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html)를 참고한다.

일반 공유의 하위 경로 권한은 웹과 WebDAV에서 사용한다. SMB에는 전체 공유 권한만 게시하며, 공유 내 어느 경로에든 거부 권한이 있는 계정은 그 공유의 SMB 접근에서 제외한다. 계정·자격 증명·공유·권한·암호화·Home 설정이 바뀌면 게시를 갱신한다. 자격 증명이나 공유 설정이 변경되면 데몬을 재시작해 이미 인증한 연결에도 새 규칙을 적용한다. 변경 없는 재게시에서는 연결을 유지한다.

그룹 멤버 추가·제거·그룹 삭제도 SMB 게시를 즉시 갱신한다. 자격 증명 가져오기나 폐기 실패 시 SMB를 중지해 이전 비밀번호와 폐기 대상 계정이 계속 접속하지 못하게 한다. 동기화가 정상화되면 감독 프로세스가 다시 적용한다.

## 연결 상태와 저장 경로

설정 → 연결은 SMB 인증 상태와 폴더 접근 상태를 구분해 표시한다. 서버 SMB 꺼짐, 서비스 연결 실패, 계정 자격 증명 미적용, Home 준비 실패, 컨테이너 마운트 누락, SMB에서 지원하지 않는 저장소·권한을 안내한다. 응답에는 현재 계정의 폴더와 SMB 공유 이름만 포함하며 서버 저장 경로와 다른 계정의 개인 공유 이름을 노출하지 않는다.

기본 Home 저장 경로는 데이터 디렉터리 아래 `homes`다. 기본 Compose는 기존 데이터 볼륨의 `homes` 하위 디렉터리만 SMB 컨테이너의 같은 경로에 마운트한다. 기존 파일을 가리는 새 볼륨을 추가하지 않으며 데이터베이스와 마스터 키를 SMB 컨테이너에 전달하지 않는다. 서버가 하위 디렉터리를 준비하고 정상 상태가 된 뒤 SMB 컨테이너를 시작한다. Compose의 `volume.subpath`는 [공식 명세](https://compose-spec.github.io/compose-spec/spec.html)에 정의되어 있다.

기본 Compose를 사용하려면 [볼륨 하위 경로를 지원하는 Docker Engine 26.0 이상](https://docs.docker.com/engine/release-notes/26.0/)과 최신 Docker Compose가 필요하다.

사용자 지정 Home 경로도 두 컨테이너에 같은 경로로 마운트해야 한다. Home 저장 루트와 일반 로컬 공유 경로는 서로 포함할 수 없으며, 심볼릭 링크로 같은 경로를 가리키는 경우도 거부한다. Home을 꺼도 파일은 보존한다. 저장 루트를 변경하면 기존 파일을 자동으로 옮기지 않는다.

## 상위 폴더 이동

파일 목록·격자 화면에는 각 공유 루트 아래에서 `.. · 상위 폴더로 이동` 버튼을 표시한다. Home과 일반 공유 폴더의 최상위에서는 숨긴다. 공개 링크에서는 링크 대상 폴더가 루트이며, 서버 경로 선택에서는 서버 API가 제공한 상위 경로가 있을 때 표시한다.

이 버튼은 파일 선택·정렬·필터·삭제·이동·페이지 개수에 포함하지 않는다. 빈 폴더에서도 사용할 수 있다.

## 검증

자동 테스트는 웹 로그인 전 생성, 기존 계정 준비, 활성화·비활성화·계정 삭제, 기존 숫자 경로 유지, 수동 권한 변경 차단, 저장 경로 겹침과 링크 차단, 개인 연결 정보 격리, 마운트 누락 안내, 변경된 권한에 따른 연결 종료를 확인한다.

실제 Samba에서는 개인 폴더 읽기·쓰기, 두 계정 간 접근 차단, 개인 공유 목록 숨김, 링크를 통한 타 계정 접근 차단, 열린 연결의 비활성화 반영, 이전 비밀번호 거부, Home 재활성화와 웹 파일 목록의 일치를 확인했다. 브라우저 테스트는 자동 Home 안내, 선택적인 공유 권한 추가, 관리 항목 분리와 준비 실패 후 재시도를 확인한다.
